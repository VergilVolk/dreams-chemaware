# ChemAware 微调主线重置（2026-08-24）

## 一、压缩后的已知事实

1. 官方 DreaMS 全局 embedding 已有较强身份检索能力，但 near 异构体与跨条件同分子仍有稳定错误。
2. 规则重叠不能作为距离标签；规则库保留为概念监督和峰级解释层。
3. 冻结 backbone + 线性 projection head 多次表现为正负相似度共同移动，不能稳定改善 near 局部顺序。
4. 第一代随机/定向删峰实验使用的最终有效样本仅 1,231 个查询、702 个身份，且候选峰被限定为低强度、低频峰；该设计主动压低了可产生的梯度。
5. M1 的条件峰整组删除相对匹配随机删除存在小而稳定的连续 margin 信号，但没有直接纠正 baseline-wrong Top-1；它只能作为后续增强候选，不能承担主监督。
6. 当前最强内部证据是 P2b 成组排序：5,037 查询 OOF Recall@1 从 0.8606 升至 0.8997（+3.91 pp），near +5.83 pp。封存 P3 primary 仍有 +1.07 pp，但 near-core 退化，说明局部谱峰证据有大 headroom，同时必须按候选难度分层。
7. 因此大信号存在于查询谱和候选谱的细粒度关系，不在单谱低强度峰的线性叠加或无条件遮蔽。

## 二、此前长期无法获得大提升的根因

- **数据饥饿**：从 57,274 条可用真实训练谱缩到 1,231 个因果配对。
- **主动选择低梯度峰**：候选强制 intensity <0.20，并排除核心峰，天然只能造成很小 embedding 位移。
- **正例挖掘不够困难**：M1 在不同条件 peer 中稳定随机选正例，没有选择真正拉开身份簇的困难正例。
- **一次一个负例**：只训练一个 hardest spectrum，未按候选分子聚合，也未使用 Top-k 负分子形成稳定组内梯度。
- **目标错位**：训练目标是候选组内检索，实验却长期测单个删峰是否让冻结模型立即改正。
- **架构容量错位**：线性 head 只能改全局度量，无法学习峰—峰局部对应、质量差和中性丢失关系。
- **噪声角色错位**：噪声应是大规模排序训练的辅助一致性视图，不应独立充当正负标签或主损失。

## 三、新主线：大规模候选组内细粒度微调

### 3.1 数据单位

每个训练单位不是单个 triplet，而是一个候选组：

- 查询谱 q；
- 同 IK14、同 adduct 的多个真实正谱，包含跨仪器/碰撞能困难正例；
- strict-10ppm、同 adduct、不同 IK14 的 Top-k 困难负分子；
- 每个候选分子可含多张谱，训练和评估均在分子层聚合。

不再要求 M0 条件峰共识才能进入主训练池。目标是覆盖全部具备真实正谱与质量邻域负例的训练身份，查询规模应达到数万，而非千级。

### 3.2 困难度与梯度优先级

官方模型先离线计算：

\[
m(q)=S_0(q,P_q)-\max_{n\in N_q}S_0(q,n).
\]

训练优先采样：

1. 官方 Top-1 错误；
2. margin 违反或接近 0 的边界查询；
3. MCES 0–2 near 负分子；
4. P2b 能修正的查询（局部谱峰证据有明确 headroom）；
5. 官方正确而 P2b 引入错误的查询作为安全回放。

禁止只取绝对最远正例；使用同身份正谱的困难分位并做离群谱质量控制，避免把错标或坏谱当正例。

### 3.3 模型

共享 DreaMS 编码器同时输出：

- precursor/global embedding z；
- 峰级 contextual token H。

候选关系得分：

\[
S(q,c)=\alpha\cos(z_q,z_c)+\beta A(H_q,H_c)+\gamma A_{NL}(q,c),
\]

其中 A 是双向峰 token 局部对齐，A_NL 是中性丢失局部对齐。它们是可学习、候选相关的证据，不是人工规则重叠标签。

候选分子的多谱得分采用预注册的 max 或 log-sum-exp 聚合，并与评价协议完全一致。

### 3.4 损失

主损失为候选组内 listwise ranking：

\[
L_{group}=-\log\frac{\sum_{p\in P_q}\exp(S(q,p)/\tau)}
{\sum_{p\in P_q}\exp(S(q,p)/\tau)+\sum_{n\in N_q}\exp(S(q,n)/\tau)}.
\]

同时保留全局 embedding 排序辅助项，确保输出的 ChemAware embedding 本身得到改善：

\[
L=L_{group}+\lambda_g L_{global-rank}+\lambda_pL_{preserve}.
\]

第一轮只比较官方 DreaMS 与 clean groupwise 模型；不加入噪声，不同时扫多个架构和损失。

### 3.5 解冻范围

- 官方 embedding 权重初始化；
- projection head + 最后一个 Transformer block 或固定的小型 adapter；
- 其余 backbone 保持 eval，关闭 dropout 混杂；
- clean-only 对照与后续 clean+noise 使用完全相同解冻范围。

## 四、噪声的正确位置

### 4.1 G0—G3 与噪声微调是一条路线，不是两条路线

G0 当前所做的候选图、错误图谱和规则全库审计，不是在规则特征上另起一个排序器，也不是放弃噪声微调。它为正式噪声微调回答三个前置问题：

1. **在哪些候选组上存在足够大的任务梯度**：官方 Top-1 错误、margin 违反、near 负分子以及 P2b 可修正查询；
2. **梯度应该作用到哪一层**：先作用于同一查询下的正分子与困难负分子的相对顺序，再进入峰 token，而不是只让全局 head 整体缩放；
3. **哪些化学观测可以约束扰动**：碎片峰、中性丢失、同位素/重排模式及其支持度，用来限制和解释噪声，不用来定义身份标签。

因此完整关系是：

\[
\text{G0 找到高梯度候选组与化学证据}
\rightarrow
\text{G1 证明 clean 候选组监督能被模型吸收}
\rightarrow
\text{G2 让梯度进入峰 token 和局部对应}
\rightarrow
\text{G3 在同一高梯度组上加入受约束噪声}.
\]

这里的“大梯度”首先由检索错误和小 margin 产生，而不是由删除峰的数量或 embedding 位移大小产生。对于候选组损失，最接近或超过正例的负分子获得最大的 softmax 梯度；已经容易判对的候选组只作为安全回放，不能主导训练。

### 4.2 噪声不是标签，而是高梯度候选组的第二观察视图

只有 clean groupwise 模型先产生稳定增益后，噪声才作为第二视图加入：

- 真实跨条件同分子谱替换为首选；
- DreaMS 强度加权随机 masking 为通用基线；
- 条件共识峰软衰减/遮蔽为 ChemAware 增量；
- 通过 clean 与 noisy 候选分布的一致性损失，而不是让噪声定义标签。

噪声分支仍使用与 clean 分支完全相同的 IK14 正例和 strict-10ppm 负候选。正式目标写为：

\[
L_{G3}=L_{clean-group}+\lambda_nL_{noisy-group}
+\lambda_cD\!\left(\pi_{clean},\pi_{noisy}\right)
+\lambda_pL_{preserve},
\]

其中 \(\pi\) 是同一候选组内的分子得分分布。该目标要求扰动后仍维持正确候选顺序，并保持 clean 与 noisy 两个观察视图的一致性；它不把“被删峰”当成负样本，也不把规则重叠当成正样本。

### 4.3 下一代定向噪声如何寻找峰级大梯度

旧 M1 先人工选低强度、低频条件峰，再整组删除；这相当于先规定答案，因此只得到接近随机删除的小信号。下一代顺序必须反过来：

1. 先在 G0 标出的 baseline-wrong、边界 margin 和 near 候选组中采样；
2. 用 G2 的候选相关峰—峰对齐，计算“哪些查询峰改变正分子与最难负分子的得分差”，而不是计算单谱 embedding 位移；
3. 在强度、删峰比例、m/z 分布和规则类别匹配的约束下，生成随机 masking 基线；
4. 只有能稳定改变候选 margin、且超过匹配随机扰动的峰级干预，才进入定向噪声池；
5. 优先采用软衰减和少量组合扰动，禁止再次无条件整组删除所谓特异峰。

峰级选择目标是候选 margin 的变化：

\[
\Delta m_k=
\big[S(q,p)-S(q,n^*)\big]
-\big[S(T_k(q),p)-S(T_k(q),n^*)\big],
\]

其中 \(T_k\) 是对第 \(k\) 个峰或峰组的受约束扰动，\(n^*\) 是同一查询的最难负分子。只有 \(\Delta m_k\) 相对匹配随机对照具有可重复的特异效应时，才称为定向噪声证据。

### 4.4 噪声微调的正式裁决

必须做 G2 clean-only vs G3 clean+noise 单变量比较，二者使用相同数据身份、候选图、解冻范围、训练步数和随机种子。噪声分支至少需要同时满足：

- identity-equal Recall@1 与 near Recall@1 不下降；
- baseline-wrong 的净修正显著为正；
- baseline-correct 的新增错误受控；
- clean embedding 与官方表征保持门通过；
- 增益在公式隔离折中方向一致。

若 noise 没有超过 G2，则保留错误图谱和因果结果，但不把噪声写成最终性能来源；这不否定 ChemAware 主模型，只说明该噪声机制未提供额外信息。

## 五、化学规则接口

规则库不再负责构造距离。它进入三个位置：

1. 对局部峰 token 对齐进行碎片/中性丢失/同位素概念监督；
2. 解释候选组内哪些峰证据推动目标分子胜出；
3. 将规则—结构冲突样本加入困难候选组，但真实 IK14/结构关系仍是标签。

## 六、开跑前的硬门

必须先生成一次只读 preflight：

- 训练查询至少 15,000；
- 独立 IK14 至少 2,500，并报告实际上限；
- 每个 query 至少 1 个真实正谱和 2 个不同 IK14 负分子；
- near 查询至少 1,500；
- 所有查询按 identity 等权，禁止高重复分子主导；
- train/validation/P3/P2b 消耗集的 IK14 重叠为 0；
- 报告 baseline 错误数、margin 分布、Top-k 负例覆盖及理论最大可提升量；
- 预估 4 pp 所需净修正数，并确认错误池足够。

任何一项不满足，不训练；先扩大候选图或修正协议。

## 七、最小实验序列

1. **G0：大规模候选图与梯度 headroom 审计**。
2. **G1：clean groupwise，全局 cosine 得分，最后一层小范围解冻**。
3. **G2：加入峰 token 双向局部对齐；其它完全不变**。
4. **G3：G2 + 条件噪声一致性；与 G2 单变量比较**。
5. 三 seed OOF 通过后冻结，建设新的未查看测试集；已查看的 P3 不再作为新模型盲测。

主结果必须分别报告：官方权重、ChemAware 全局 embedding cosine、完整细粒度 scorer。这样可以区分 embedding 真改善与候选交互模块带来的额外增益。

## 八、G0 正式执行合同（固化，后续不得缩水）

### 8.1 数据范围

- 直接复用已经构建的全量真实候选图 `g8r_error_atlas_listwise_cache.npz`，不再使用每个身份最多两张谱的 5,037-query P2 子集作为主训练规模。
- G0 对缓存中的全部查询做审计；只有 smoke test 可以限制查询数，任何带 `formal` 标记的结果若不是全量必须失败。
- 查询按 IK14 等权汇总，同时保留谱图级结果。高重复身份不能因为谱图多而支配总体结论。
- 每个训练查询必须同时具备真实同身份正谱和至少两个不同身份的 strict-10 ppm、同 adduct 负候选分子。少于两个负分子的查询只进入覆盖审计，不进入 G1 主训练池。

### 8.2 4 个百分点可行性门

G0 必须同时报告：

1. 全部可训练查询、IK14、分子式、near 查询数量；
2. 官方 DreaMS 的 Top-1 错误数和 identity-equal Recall@1；
3. 提升 4 pp 所需的谱图级净修正数与身份等权净修正量；
4. 在固定幅度残差下几何可达的错误数；
5. 至少一种不看答案的单一局部证据，以及仅用于 headroom 的 per-query oracle，能够覆盖多少官方错误；
6. 每个公式隔离折中的错误数、near 数和可恢复错误数。

只有当全量错误池和局部证据 headroom 都足以覆盖 4 pp，才允许进入 G1。Oracle 只证明数据里有信号，不能作为模型结果。

### 8.3 化学规则全库审计

G0 不抽取一个方便的小规则子集。对全部可达真实谱图计算：

- 335 条机制/经验核心规则；
- 3,151 条 MassBank 记录衍生规则；
- 合并后的 3,486 维谱图级观测向量。

为避免 3,486 个稀疏二值量直接污染模型，正式输出同时保存 packed-bit 向量和以下预定义候选对证据：

- 核心规则 Jaccard；
- MassBank 规则 Jaccard；
- CF、前体—碎片中性丢失、ISO、HR、NR、EE 分类 Jaccard；
- MassBank 中由 `|precursor_mz-exact_mass|` 生成的 79 条记录单列为前体/中性质量偏移，禁止称为碎片中性丢失；
- 规则支持正例、规则支持错误候选、规则证据缺失三种状态；
- 规则覆盖率、独立身份支持度、来源和支持度分层。

两谱均未命中规则时 Jaccard 记为缺失，不得记为 1。规则仍是谱图质量模式，不是结构标签。MassBank 单记录规则不得因为数量多而获得更高总权重。

旧的谱图标签脚本曾把所有 `mass_diff` 匹配到任意峰—峰差值。G0 正式口径已修正：核心 NL 匹配 `precursor_mz-fragment_mz`；ISO/HR 保留峰—峰差；MassBank 的前体/中性质量偏移使用 HDF5 的 `PARENT_MASS` 单独匹配。旧口径只用于历史结果解释，不得继续生成正式监督。

### 8.4 G0 产物

- `g8r_chemaware_g0_rule_cache.npz`：全部可达谱图的 packed 3,486 维规则向量；
- `g8r_chemaware_g0_rule_cache.json`：覆盖率、身份支持度、来源分层和哈希；
- `g8r_chemaware_g0_full_audit.json`：规模、错误、margin、headroom、公式隔离折和规则证据结果；
- `g8r_chemaware_g0_query_priority.csv.gz`：后续 G1 的查询优先级，但不包含任何 P3 身份；
- `g8r_chemaware_g0_pair_rule_features.npz`：与候选图严格对齐的规则证据特征。
