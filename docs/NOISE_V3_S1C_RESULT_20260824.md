# Noise-v3 S1c 扩展单峰动作矩阵结果

日期：2026-08-24

## 1. 数据完整性

- 正式候选图：23,876 个 query；
- 官方 DreaMS 错误：1,805 个，Recall@1 = 0.924401；
- 动作空间：candidate-gradient 前 5 个峰、role-confounder 前 3 个峰；
- 剂量：25%、50%、75%、100%；
- 输出包含 394,752 个 query-action 行；
- 单元测试、候选图预检和矩阵完整性门均通过。

原始矩阵和各动作统计有效。下载的旧 headroom JSON 误用了 S1b 的状态名及 1 pp 阈值，因此其中 `pass_to_policy_design=true` 不是 S1c 的正式裁决。

## 2. 主要结果

### 2.1 no-op-aware oracle 上限

- 任一非对照动作可修正的独立错误：408；
- 理论 Recall@1 上限：0.941489；
- 理论增益：+0.017088，即 +1.709 pp；
- near 错误中可修正：347 / 1,446，约 24.0%。

该 oracle 使用真实动作结果为每个 query 事后选择动作，只代表动作空间上限，不是模型成绩。

### 2.2 与 S1b 的增量

- S1b 单峰动作空间：386 个独立可修正错误；
- S1c 扩展动作空间：408 个独立可修正错误；
- 扩展 4 个 gradient rank 和 2 个 confounder rank 后，只新增 22 个独立错误。

与此同时，正动作行显著增加至 2,176。由此可见，大多数新增动作重复修正同一批 query，并未有效扩大错误覆盖。

### 2.3 两类选择器的互补性

- candidate-gradient 可修正 370 个错误；
- role-confounder 可修正 113 个错误；
- 交集 75；
- gradient 独有 295；
- confounder 独有 38。

两类选择器确有互补信息，但 confounder 的独立覆盖较小，不能单独承担大幅性能提升。

## 3. 正式裁决

S1c 的预注册硬门为：

1. oracle 至少达到 +2.0 pp，即至少修正 478 个独立错误；
2. 优先达到至少 600 个独立可修正 query；
3. 两类选择器均保留独有修正。

实测为 408 个、+1.709 pp，因此前两项失败。结论是：

> 扩展单峰位置不能提供足够的性能头寸，暂不进入高容量非线性策略学习。下一步应检验顺序多峰组合是否带来新的独立纠错覆盖，而不是继续增加单峰 rank。

## 4. 下一步 S2 的边界

S2 只回答“多个具有方向依据的峰按顺序干预，能否产生超出单峰并集的新修正”。必须满足：

- 每一步均重新计算候选组 margin 和下一峰；
- 最多 3 步，每一步可 stop；
- 预注册 50% 与 100% 两档，不做大规模剂量搜索；
- 同步运行相同峰角色、相同强度和相同步数的随机序列；
- 分别报告 step1、step2、step3 新增的独立 corrected、introduced 和 formula-cluster CI；
- 若 step2/step3 不能把独立 oracle 提高到至少 478 个，停止该噪声动作空间，不以“大幅提升”包装；
- 只有通过头寸门后，才训练可选择 no-op 的查询级策略头并进入正式微调。
