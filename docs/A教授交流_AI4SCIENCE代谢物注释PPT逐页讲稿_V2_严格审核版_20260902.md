# 与 A 教授交流：AI for Science 代谢物注释课题 PPT 逐页讲稿

**版本：** V2 严格审核版（2026-09-02）  
**适用场景：** 与 A 教授第一次正式交流；18–22 分钟主讲，20–30 分钟讨论  
**听众假设：** AI、算法和大规模计算背景强；未必熟悉代谢组学、LC–MS/MS 和鉴定等级  
**交流性质：** 共同定义科学问题，不是汇报本组算法，不是展示阶段成绩，也不是当场申请算力  
**建议参会目标：** 会后双方能够决定是否值得共同冻结一期任务，而不是要求对方现场决定具体技术路线

---

## 一、先把这次交流的“任务”说清楚

### 交流结束后，希望 A 教授准确理解四件事

1. **科学问题是什么：** 如何把一张未知小分子 MS/MS 谱图转化为可信、可验证的结构结论。
2. **输入是什么：** 峰表、母离子信息、实验条件，以及不同任务下允许使用的候选结构空间。
3. **输出是什么：** 不是强制给一个名称，而是候选排序、置信度、证据、结论层级和必要时的拒答。
4. **怎样算做对：** 计算基准上的检索正确、盲标准品上的身份确认、真实队列中的可重复和可验证，三者必须分层表述。

### 建议贯穿全场的一句话

> **我们希望研究的，不是让模型对每张谱都猜一个名字，而是让它在证据允许的范围内，给出尽可能具体、置信度可校准、能够被实验验证的代谢物结构结论。**

### 必须坚持的科学边界

- 单张 MS/MS 往往不能唯一确定完整结构，尤其面对立体异构体、位置异构体和库外分子。
- “候选池中第一名正确”是计算检索结果，不等于真实样本中的化学身份已经确认。
- 公共谱库匹配通常只能支持概率性结构注释；Level 1 仍需要同分析条件下的真实标准品和正交证据。
- 真实队列中的未知峰通常没有逐一真值，不能直接计算“全部未知峰准确率”。
- 算力可以扩大假设搜索和实验覆盖，不能自动补足缺失真值，也不能消除信息不可辨识性。

# 三、逐页内容与可直接使用的讲稿

## 第 1 页｜封面：先说明今天不是算法汇报

### 页面标题

**从串联质谱到可信的代谢物结构结论**  
副标题：一个可规模化探索、也可被严格否证的 AI for Science 问题

页面下方只放汇报人、双方单位和日期。不要出现 ChemAware、BioAware、内部模型名、实验编号或性能数字。

### 页面视觉

左侧一张简洁的 MS/MS 棒状谱，右侧三个相近的候选结构，中间放一个问号。视觉只回答一个问题：**观测到碎片以后，原分子是谁？**

### 讲稿（约 45 秒）

“A 老师您好。今天我们不是来汇报一套已经定型的算法，而是想和您讨论一个可能适合大规模 AI for Science 推进的科学问题：能否从小分子的串联质谱出发，得到可信、可验证的结构结论。

我们主要讲三件事：模型拿到的输入究竟是什么；最后应该输出什么；以及怎样才能严格说明它做对了。最后我们再讨论，为什么这个问题可能适合大规模 Agent 做并行假设探索，以及双方可以从什么样的一期任务开始。”

### 本页不能说

- “我们有一个课题，希望贵组帮我们把算法做出来。”
- “贵组有大量算力，正好可以用来暴力搜索。”
- “我们已经找到正确路线，只差算力。”

### 转场

“先从实际研究中的瓶颈说起：仪器已经测到了大量信号，但这些信号究竟是什么分子，往往并不知道。”

---

## 第 2 页｜问题的价值：测得到，不等于认得出

### 页面标题

**非靶向代谢组学已经产生大量信号，但多数 MS/MS 仍没有可靠的结构身份**

### 屏幕上只保留三层信息

1. 生物样本 → LC–MS/MS → 大量谱图；
2. 少量有可靠结构注释，大量仍未知；
3. 没有结构身份，差异信号很难进入通路解释、机制研究和后续标准品验证。

可在角落放一条有来源的量级提示：DreaMS 论文援引相关研究指出，参考谱库通常只能注释约 2% 的 MS/MS，现有机器学习工具通常也低于 10%。页面必须写“典型研究中的估计”，不能写成对所有实验都成立的固定比例。

### 讲稿（约 80 秒）

“非靶向代谢组学的特点，是不预先规定只测哪些分子，而是尽可能广泛地采集样本中的代谢信号。一次实验可以产生大量峰和大量串联质谱，但仪器记录的是离子的质量和碎裂结果，不会直接返回一个可靠的分子名称。

因此，当前的矛盾不是没有数据，而是有大量观测没有结构身份。没有结构身份，一个差异峰很难可靠地进入通路、作用机制或者后续实验。DreaMS 论文给出的背景量级是：在典型非靶向实验中，参考谱库能够覆盖的比例很低，机器学习工具能够分配结构的比例通常也不到 10%。这个数字不是所有平台的统一定律，但足以说明结构注释仍是主要瓶颈。

所以，这个问题的科学价值不是把一个结果表填满，而是把原本不可解释的信号，转化为可以被化学实验继续验证的候选。”

### 听众友好说明

第一次说“非靶向代谢组学”时，紧接一句：**“也就是事先不限定分子清单，尽可能广泛地测。”**

### 转场

“问题为什么难？关键在于 MS/MS 提供的是碎裂后的部分观测，而我们要反推出碎裂前的结构。”

---

## 第 3 页｜科学问题：它不是普通分类，而是开放世界反问题

### 页面标题

**任务是从不完整、条件依赖的碎裂观测反推结构，而且正确答案可能不在库中**

### 页面内容

左侧用三步图说明观测过程：

`母离子 → 碰撞碎裂 → {(m/z, intensity)}`

右侧只列四个根本困难：

- **多解性：** 不同结构可能具有相同质量和相似碎片；
- **条件依赖：** 仪器、碰撞能量、离子模式和加合物会改变谱图；
- **标签稀缺：** 亿级谱图中，只有少量谱图带可靠结构；
- **开放世界：** 真分子可能没有参考谱，甚至不在候选库中。

### 建议正式定义

> 给定一张未知小分子 MS/MS 谱图及其采集上下文，系统能否在候选存在时找回正确结构；在候选缺失或证据不足时，退回到分子式、结构家族或未知，并给出可校准的不确定性？

### 讲稿（约 110 秒）

“MS/MS 可以理解为一次受控的分子破碎实验。仪器先选择一个母离子，再让它碰撞碎裂，最后记录碎片的质荷比和相对强度。模型看到的不是结构本身，而是结构在特定实验条件下留下的一组不完整观测。

这个反演并不是一一对应。相同分子式可能对应很多异构体，它们会产生部分相同的碎片；同一个分子换一台仪器、换一个碰撞能量，谱图也可能变化。更现实的是，真正的分子可能从未被标准品测过，因此不在现有参考谱库中。

所以我们建议把科学问题分成两个层级。第一层是候选池内检索：如果正确结构确实在候选集合中，系统能否把它排到前面。第二层是开放世界判断：如果正确结构不在候选集合中，系统能否识别证据不足，退到分子式、结构家族或者未知，而不是从错误候选中强行选一个。

这个分层很重要。它避免把单张 MS/MS 能提供的信息说得过满，同时也保留了真正值得攻关的前沿问题。”

### 本页不能说

- 不说“MS/MS 是分子的唯一指纹”。
- 不说“目标就是从一张谱恢复唯一完整结构”。
- 不说“只要模型足够大，异构体问题就会自然消失”。

### 转场

“为了避免后面被数据库名称带跑，我们先把一期任务写成一张非常明确的任务卡。”

---

## 第 4 页｜一页任务卡：输入、输出、真值、边界

### 页面标题

**一期任务可以冻结为：给定谱图和固定候选，正确排序；候选缺失时，能够识别并拒答**

### 页面中央四行即可

| 要素 | 一期建议定义 |
|---|---|
| 输入 | 一张标准化 MS/MS 峰表 + precursor m/z + 离子模式/加合物 + 可用实验条件 |
| 候选 | 由精确质量或已知分子式产生的固定结构候选集合 |
| 输出 | Top-k 结构 + 校准置信度 + 支持/冲突证据 + 拒答状态 |
| 真值 | 已知结构的冻结测试谱；外加“移除真值”的开放世界压力测试 |

页面底部写一句边界：**一期不是要求从整个化学空间一次生成唯一结构，而是先把可比较、可否证的核心任务做严。**

### 讲稿（约 90 秒）

“如果双方要共同推进，我们建议先冻结一个足够清楚的一期任务。输入是一张标准化 MS/MS 谱图，加上母离子质量、离子模式、加合物和能够获得的实验条件。根据精确质量或者已知分子式，从固定结构库中产生候选。系统输出 Top-k 候选、置信度、支持和冲突证据，以及是否拒答。

真值来自结构已知、身份冻结的参考谱。除此之外，我们还要人为构造一类压力测试：把正确结构从候选池中拿掉，看系统会不会仍然高置信地选错。这直接检验开放世界可靠性。

一期先不要求模型从整个化学空间一步生成唯一结构。原因不是降低问题价值，而是先建立一个不同团队、不同模型都能在同一条件下比较的科学任务。基础协议成立后，再扩展到分子式推断、结构生成和实验验证。”

### 可能被问：为什么不直接做 de novo 结构生成？

建议回答：“可以作为第二条前沿支线，但当前完整结构精确命中的难度极高，而且生成结果的真值、等价结构处理和实验确认更复杂。先用固定候选检索建立可靠基线，更容易判断算力和 Agent 带来的真实增益。”

### 转场

“接下来先把这里所说的一条标准输入记录具体展开。”

---

## 第 5 页｜输入数据：模型真正拿到的不是图片

### 页面标题

**最小输入是峰表和母离子信息；实验上下文决定模型能否跨平台泛化**

### 页面内容

```text
spectrum_id
peaks = [(m/z_1, intensity_1), ..., (m/z_n, intensity_n)]
precursor_mz
ion_mode / charge / adduct
collision_energy / instrument_type      # 如有
retention_time / chromatography         # 如有
sample_id / study_id                     # 真实队列中保留
```

格式链路放在页面下方：

`厂商 RAW → mzML/mzXML → MGF/MSP/JSON → 清洗后的 HDF5/张量`

实验设计和样本关系另以 `ISA-Tab / TSV / JSON metadata` 保存。

### 讲稿（约 90 秒）

“对模型而言，一张谱不是图片，而是一组峰。每个峰由质荷比和相对强度组成，同时必须知道母离子的质荷比。电离模式、电荷和加合物决定观测质量如何对应到中性分子；碰撞能量和仪器类型会改变碎裂；保留时间和色谱条件则提供额外上下文。

数据从仪器出来时通常是厂商专有 RAW 文件，公共仓库常提供或可转换为 mzML、mzXML。谱库交换常见 MGF、MSP 或 JSON。进入大规模训练时，可以转成便于随机读取的 HDF5 或张量，但转换过程必须保留原始记录、处理版本和元数据映射。

这里我们希望和计算团队一起解决的第一个问题，其实就是数据标准化：哪些字段必须保留，哪些缺失可以容忍，如何去除空谱、污染谱、重复谱和错误前体。数据清洗本身就是科学任务的一部分。”

### 本页不能说

- 不把固定峰数、token 数、某个网络输入张量写成课题的唯一输入定义。
- 不把 retention time 说成所有公共数据都完整具备。
- 不说“mzML 就是训练格式”；它是开放交换格式，训练时通常还会再次整理。

### 转场

“有了输入格式以后，下一步不是列一长串数据库，而是先说明每类数据在任务中扮演什么角色。”

---

## 第 6 页｜数据组织：五类数据不能混成一张优先级表

### 页面标题

**无标注谱图、参考谱库、候选结构库、冻结基准和真实队列承担不同角色**

### 页面内容

按任务链从左到右放五类数据：

1. **无标注谱图语料**：学习真实谱图分布；代表为 MassIVE-GNPS / GeMS。
2. **带结构参考谱库**：提供谱图—结构配对；代表为 MoNA、MassBank，授权条件下可补 NIST。
3. **候选结构与化学知识**：定义可搜索结构空间；代表为 PubChem、HMDB。
4. **冻结计算基准**：统一切分、候选和指标；代表为 MassSpecGym。
5. **盲标准品与真实队列**：验证跨条件泛化和实际可用性；代表为独立标准品面板、MetaboLights 研究。

在页脚单独写：**KEGG、MetaCyc、BRENDA 等更适合后续反应、通路和生化约束，不是 MS/MS 结构学习的主要真值来源。**

### 讲稿（约 90 秒）

“这五类数据不能用一个‘优先级’直接混排，因为它们回答的是不同问题。MassIVE 和 GeMS 规模很大，但绝大多数没有结构标签，适合学习真实谱图分布。MoNA 和 MassBank 较小，却包含谱图与已知结构的配对，适合监督训练和参考检索。PubChem、HMDB 主要提供候选结构；一个结构被数据库收录，并不代表它一定有实验 MS/MS。

MassSpecGym 的作用是冻结评测条件。最后，盲标准品和真实研究队列负责判断模型离开公共题库后是否还能工作。

KEGG、MetaCyc、BRENDA 这类资源很重要，但它们主要提供反应、通路、酶和生化上下文。它们可以支持后续的生物学解释或候选约束，不能替代谱图—结构真值。”

### 现场措辞提醒

不要说“MOA 大于 MoNA、MassIVE”或“HMDB 大于 MassSpecGym”。更自然、也更严谨的说法是：**“不同阶段使用不同数据，不能跨角色比较优先级。”**

### 转场

“先看最适合大规模预训练的一类：公共仓库里数量巨大的无标注谱图。”

---

## 第 7 页｜DreaMS/GeMS：大算力首先面对的是无标注数据

### 页面标题

**公开仓库已有亿级 MS/MS；DreaMS 将其中 2400 万张高质量谱整理为预训练语料**

### 页面只放四个数字，并写清口径

- `338,649` 个 MassIVE-GNPS 文件进入初始筛选；
- `249,422` 个文件包含 MS/MS，共约 `814 million` 张原始 MS/MS；
- 去除空谱和非法记录后，完整 GeMS 约 `714 million` 张；
- DreaMS 预训练使用高质量、限簇大小的 `GeMS-A10`，约 `24 million` 张。

旁边注明：

- 时间口径：DreaMS 作者整理的 2022 年 11 月 MassIVE-GNPS 快照；
- 输入来源：mzML/mzXML；
- 整理形式：带部分 LC–MS/MS 元数据的紧凑 HDF5 数值数据；
- 标签情况：绝大多数没有分子结构标签。

### 讲稿（约 100 秒）

“DreaMS 的重要启示之一，是公共质谱仓库已经达到基础模型的数据规模。作者从 2022 年 11 月的 MassIVE-GNPS 快照中筛选了 33.8 万多个文件，其中约 24.9 万个包含 MS/MS。原始提取约 8.14 亿张谱，去除空谱和非法记录后，完整 GeMS 仍约有 7.14 亿张。

但 DreaMS 并没有简单地把全部数据都用于训练。作者进一步按质量筛选和相似谱聚类，最终使用约 2400 万张高质量 GeMS-A10 谱进行自监督预训练。这个结果说明一个重要事实：在质谱中，规模不是唯一变量，数据质量、重复度和实验分布同样决定表示能否学到有效信息。

这些谱大多没有结构标签。因此，大规模算力的第一个自然入口，是从海量真实观测中学习稳定的谱图表示；但仅靠无标注数据，还不能直接建立每张谱与唯一结构的真值关系。”

### 本页必须避免的数字混淆

- `714 million`：清除空谱和非法记录后的完整 GeMS；
- `24 million`：用于 DreaMS 预训练的 GeMS-A10；
- `201 million`：DreaMS Atlas 所用 GeMS-C 子集对应的谱图规模；
- `76 million`：Atlas 中生成 embedding 的 GeMS-C1 代表谱规模。

四个数字不得合并成“DreaMS 训练集有 7 亿/2 亿/7600 万”。

### 转场

“无标注数据解决表示学习，但要让表示对齐到结构，还需要带真值的谱库、候选结构库和统一评测集。”

## 第 8 页｜MoNA、候选库和 MassSpecGym：三种资源，三种职责

### 页面标题

**带标签谱库负责对齐结构，候选库负责定义搜索空间，基准负责判断模型是否进步**

### 页面三列内容

#### MoNA：带结构参考谱库

- 内容：实验或计算谱、precursor/adduct、碰撞条件、SMILES/InChIKey 等；
- 常见格式：MSP、JSON、SDF；
- DreaMS 论文使用的 MoNA 划分：训练 `25,319` 张谱 / `5,524` 个分子；验证 `3,557` 张谱 / `831` 个分子；合计约 **2.9 万张谱、6,355 个分子**；
- 注意：上述数字是 DreaMS 的特定清洗与切分，不是 MoNA 官网当前全库规模。

#### PubChem / HMDB：候选结构与属性

- 内容：分子式、精确质量、SMILES、InChI/InChIKey、理化或生物信息；
- 常见格式：SDF、SMILES、XML、JSON、CSV；
- 作用：按质量或分子式生成候选；不等同于“有实验参考谱”。

#### MassSpecGym：冻结计算基准

- 约 `231k` 张标准化 MS/MS、约 `29k` 个独特结构；
- 来源包括 MoNA、MassBank、GNPS 和研究组数据；
- 候选检索中按质量构造候选，单个 query 最多 256 个；
- 以 MCES 距离做结构隔离切分，降低近重复结构泄漏。

### 讲稿（约 110 秒）

“这三类资源经常被放在一起，但作用完全不同。MoNA 提供带结构标签的参考谱。DreaMS 论文用于相似性微调的特定 MoNA 划分，训练和验证合计约 2.9 万张谱、6355 个分子。这里一定要注明，这是论文特定清洗和切分后的规模，不是 MoNA 官网随时间变化的全库规模。

PubChem 和 HMDB 主要提供结构与属性。它们适合按母离子精确质量或者分子式生成候选，但数据库中有一个结构，并不意味着这个结构已经有高质量实验谱。

MassSpecGym 则把机器学习任务标准化。它整理了约 23.1 万张谱和约 2.9 万个独特结构，并提供候选检索、结构生成和谱图预测等任务。对我们这次交流最重要的是候选检索：给定一张谱和最多 256 个质量匹配候选，模型能否把真结构排到前面。它还使用结构距离隔离训练和测试，减少近重复分子带来的虚高。”

### 可能被问：为什么不用 NIST？

建议回答：“NIST 是重要的高质量谱库，但属于授权资源。若一期强调公开、可复现，先以公开谱库和基准为主；在双方具备合规授权时，再作为补充外部测试。”

### 转场

“计算基准告诉我们模型会不会做有答案的题；真实队列则告诉我们它离开题库以后是否仍然可用。”

## 第 9 页｜真实队列：MTBLS13729 是压力测试，不是课题本身

### 页面标题

**真实队列用于检验完整流程和产生待验证候选，不能替代有真值的准确率测试**

### 页面内容

左侧事实：

- MetaboLights 公开研究，CC0 1.0；
- 30 位结直肠癌患者的肿瘤与匹配正常组织，共 60 个样本；
- 4 个 LC–MS 面板：HILIC/RPLC × 正/负离子；
- 对应 4 × 60 = 240 条 assay 记录；当前公开元数据把 mzML 列在 `Derived Spectral Data File`，并配套 ISA-Tab/assay metadata；
- 真实组织、不同色谱和离子模式，大量信号没有逐一标准品真值。

右侧作用：

1. 测试从原始文件到结构候选的完整流程；
2. 检查跨色谱、离子模式和真实样本的稳定性；
3. 选择最值得购买标准品或做靶向验证的候选；
4. 不用它宣称“全部未知谱 Top-1 准确率”。

### 讲稿（约 80 秒）

“MTBLS13729 可以作为真实应用示例，但不是整个课题的边界。它来自 MetaboLights，包含 30 位结直肠癌患者的肿瘤和匹配正常组织，共 60 个样本，并采用 HILIC 和反相色谱、正负离子四个分析面板，因此四张 assay 表合计有 240 条记录和配套实验元数据。这里要注意数据口径：当前元数据的 `Raw Spectral Data File` 字段为空，公开 mzML 列在 `Derived Spectral Data File`，所以我们称它们为 assay 关联的 mzML 文件，不称为厂商原始 RAW 文件。

这类数据的价值，是检验从公开 mzML、谱图提取、候选排序到生物学分析的完整流程，也可以帮助我们筛选最值得做标准品验证的候选。

但真实队列中的大量未知峰没有逐一结构真值。所以它不能用来直接计算所有未知谱的 Top-1 准确率，更不能把模型给出的名称直接当作确认身份。它是外部压力测试和实验验证入口，不是训练模型只服务于这一个数据集。”

### 本页不能展示

- 本组在该队列上的候选名称、显著性结果或内部模型提升；
- 将差异丰度、通路富集或队列相关性当成结构真值；
- “在 MTBLS13729 上准确率提升”之类没有逐谱真值支持的表述。

### 转场

“数据边界明确以后，下面回答第二个核心问题：系统最终到底应该交付什么。”

## 第 10 页｜最终目标：输出分层结论，而不是强制命名

### 页面标题

**系统最终应交付候选、置信度、证据和拒答，并明确结论处于哪一层**

### 页面内容

输入一张未知谱以后，系统输出五项：

1. **候选排序：** Top-k 结构、分子式、SMILES/InChIKey；
2. **校准置信度：** 该结论在同类样本中的实际可靠程度；
3. **支持证据：** 哪些碎片、质量约束和实验条件支持候选；
4. **冲突与缺失：** 哪些关键峰不匹配、候选库是否可能不完整；
5. **结论层级：** 完整结构候选、结构家族、分子式或未知，并允许拒答。

页面底部写成功定义：

> **候选存在时尽量把真结构排到前列；候选缺失或证据不足时，不制造虚假的确定性。**

### 讲稿（约 95 秒）

“如果把最终目标只写成‘输出一个代谢物名称’，任务会被定义得过于粗糙，也容易诱导模型在每张谱上强行猜测。

我们希望系统至少交付五类信息：Top-k 候选；经过校准的置信度；支持候选的碎片和质量证据；不支持它的冲突证据；以及最终结论能够具体到哪一层。证据足够时可以给完整结构候选；证据不足时，应退到结构家族、分子式或者未知。

这里的置信度不是模型内部一个未经校准的分数，而是要能回答：在系统给出相同置信度的一批结果里，大约有多少最终能够被真值验证。拒答也不是失败，而是科学可靠性的一部分。一个系统如果覆盖率略低，但能显著减少高置信错误，可能比对所有谱都给名字更有价值。”

### 可能被问：最终到底追求覆盖率还是准确率？

建议回答：“两者不能只选一个。应报告 accuracy–coverage 或 risk–coverage 曲线：在不同拒答阈值下，系统覆盖多少谱、剩余结果有多可靠。具体阈值由下游实验成本决定。”

### 转场

“输出定义以后，第三个核心问题就是：怎样判断模型真的变强，而不是换了数据、换了候选或者利用了泄漏。”

## 第 11 页｜第一层评价：模型能力是否真的变强

### 页面标题

**只有在同一 query、同一候选池和同一切分下，模型间的性能变化才可比较**

### 页面上半部分：冻结协议

- 按完整分子身份或结构簇切分；同一分子的重复谱不能跨训练和测试；
- 候选生成规则固定：质量窗口、分子式条件、数据库版本全部锁定；
- 输入预处理、谱图聚合、并列处理和缺失字段规则固定；
- 超参数和阈值只在训练/验证集选择；冻结测试集最后运行；
- 统计单位优先按分子或分子式簇，而不是把同一分子的多张谱当成完全独立样本。

### 页面下半部分：指标分四组

1. **排序能力：** Hit/Recall@1、@5、@20，MRR；
2. **结构接近程度：** MCES@1、指纹相似度等；
3. **困难分层：** 近异构体、跨仪器、跨碰撞能量、低质量谱、低频结构；
4. **可靠性：** ECE/Brier、accuracy–coverage、拒答率，以及 corrected/introduced。

### 讲稿（约 120 秒）

“模型能力是否变强，首先要在有结构真值的冻结基准上判断。最重要的不是选择一个漂亮指标，而是先保证比较协议相同。

训练、验证和测试必须按分子身份或更严格的结构簇隔离；同一分子的不同谱不能跨集合泄漏。候选库版本、质量窗口、分子式条件、谱图预处理和并列规则都要锁定。测试集只在模型和阈值全部冻结以后运行。

指标上，Top-1 回答第一名是否正确；Top-5、Top-20 回答能否缩小实验验证范围；MRR 看整体排名。对于没有精确命中的结果，还要看第一名与真结构相差多远，例如 MCES 距离。

平均成绩之外，必须单独报告近异构体、跨仪器、跨碰撞能量和低质量谱。还要报告置信度校准与拒答曲线，并统计纠正了多少旧错误、又引入了多少新错误。只有这样，我们才能区分‘平均分提高’和‘真正获得更可靠的结构判断能力’。”

### 本页必须强调的比较纪律

**不同数据集、不同 query、不同 candidate 规则下的百分点不能相加，也不能直接宣布谁优于谁。** DreaMS 或任何后续模型，都只在完全匹配的评价协议下比较。

### 可能被问：什么是最关键的主指标？

建议回答：“一期可以预注册 Hit@1 为主指标，Hit@5、MRR、MCES@1 和校准为共同次指标；同时设置近异构体与跨条件的最低不退化门槛。单一指标不足以支持科学结论。”

### 转场

“计算测试回答模型会不会做有答案的题，但它仍然没有回答真实样本中的化学身份是否被确认。”

---

## 第 12 页｜第二、三层评价：从计算真值到化学确认

### 页面标题

**检索第一不等于身份确认；真正的验证要经过盲标准品和真实外部应用**

### 页面用三级阶梯

#### A. 封闭计算真值

已知谱 + 已知正确结构 + 固定候选池。  
可以说：**“检索正确”“排名提高”“结构更接近真值”。**

#### B. 盲标准品与跨条件测试

模型开发完成后才揭盲；标准品在同分析条件下采集，并增加跨仪器、跨碰撞能量或跨实验室复测。  
检查：Top-k 命中、置信度校准、RT 与 MS/MS 一致性、跨条件稳健性。  
可以说：**“标准品确认”“外部泛化成立”。**

#### C. 真实研究队列

报告：覆盖率、拒答率、跨重复稳定性、候选完整率、标准品验证命中率。  
没有本实验标准品时，只能说：**“结构注释”“Level 2 候选”“待验证候选”。**

### 讲稿（约 120 秒）

“这一页决定我们最后能用什么语言描述结果。封闭基准上的 Top-1 正确，只说明模型在给定候选中找到了已知真值，不能自动等同于真实样本中的化学身份确认。

更强的验证是盲标准品面板。模型和阈值冻结以后，再揭示标准品身份；最好在不同仪器、碰撞能量或实验室重复采集，检验系统是否真正学到了能够迁移的结构信息。

对于 LC–MS 代谢组学，保守的 Level 1 表述要求真实标准品在相同分析条件下测量，并至少比较两种独立、正交的分析性质。实际设计中，我们建议至少同时核对保留时间和 MS/MS，准确质量作为必要支持。只有公共谱库匹配而没有本实验标准品时，通常应称为 Level 2 的概率性结构注释。

真实队列则用于检验流程是否可用：系统覆盖多少信号、拒答多少、重复采集是否稳定，以及送去做标准品验证的候选有多少最终命中。模型的价值是缩小实验验证空间，而不是取消实验真值。”

### 语言红线

| 实际证据 | 可以说 | 不可以说 |
|---|---|---|
| 冻结候选池中 Top-1 正确 | 检索正确、排名第一 | 已在真实样本中鉴定该代谢物 |
| 公共谱库高相似匹配 | 高置信结构注释、Level 2 候选 | 唯一结构已确认 |
| 精确质量或分子式一致 | 分子式候选、结构家族候选 | 已确定具体异构体 |
| 同条件真实标准品 + 正交性质一致 | Level 1 确认 | 仍需按实际证据避免过度外推机制 |

### 转场

“当输入、输出和否证标准都明确以后，这个问题才真正适合交给大规模 Agent 体系。”

---

## 第 13 页｜合作价值：大规模探索必须被同一套真值约束

### 页面标题

**这个问题适合规模化 Agent，不只因为数据大，更因为每条路线都能被统一协议验证或否定**

### 左侧：为什么适合大规模并行探索

1. **数据规模充足：** 亿级无标注谱图、十万级标准化有标签数据；
2. **问题可以拆分：** 数据质控、谱图表示、候选生成、碎裂推理、结构生成、校准与拒答；
3. **假设空间很大：** Agent 可并行提出训练目标、化学约束、数据组合和失败解释；
4. **可以自动反驳：** 所有方案回到同一冻结基准、负对照和盲标准品；
5. **实验终点明确：** 高价值候选可以进入标准品和靶向验证。

### 右侧：建议的一期合作产物

- 一份冻结的 **Task Card**：输入、输出、候选、真值和禁止泄漏边界；
- 一套 **公开数据清单与许可证台账**；
- 一个 **结构隔离的计算基准**；
- 一个 **候选移除的开放世界压力测试**；
- 一个 **独立盲标准品面板**；
- 一套让 Agent 自动记录假设、实验、负结果和复现信息的审计规范。

页面底部的讨论问题：

> **如果这个问题值得推进，双方是否先共同冻结一期任务和验收标准，再决定最值得投入大规模算力的研究分支？**

### 讲稿（约 100 秒）

“我们认为这个问题适合规模化 Agent，并不只是因为谱图数量大。它还有一个更重要的特点：研究空间可以被拆成许多相对独立的假设，而每个假设都能够回到同一套真值协议接受验证。

Agent 可以并行处理数据质控、表示学习、碎裂约束、候选检索、结构生成和置信度校准，也可以主动寻找失败案例、设计负对照和复现实验。但大规模搜索必须被统一评测约束，否则只是扩大试错数量，不能形成可信的科学结论。

所以我们建议第一步不先规定某一种算法，也不要求现在就决定投入多少算力。更稳妥的方式，是双方共同冻结一份任务卡、公开数据和许可台账、结构隔离基准、候选移除压力测试和盲标准品面板。协议一旦稳定，再让不同 Agent 在同一边界内并行探索，才容易判断哪些提升是真实的。

我们希望听听您的判断：这个问题是否值得作为一期 AI for Science 任务；如果值得，您更关心表示学习、结构推理，还是可靠性与自动验证？”

### 收尾语气

说完后停下来讨论，不再追加“我们已经做了什么”。若 A 教授主动询问本组基础，再打开附录，用一页说明已有数据和工程准备，但仍不讲内部算法试错史。

| BRENDA / SABIO-RK / eQuilibrator | 酶、动力学、热力学约束 | enzyme、reaction、kinetics、ΔG | 表格、API、结构化导出 | 用于后续生化约束，不是谱图结构真值 |
| MOA 药物扰动图谱 | 下游生物学验证 | 药物 × 代谢特征响应 | 表格/补充数据 | 不替代谱图训练集和标准品真值 |

## 附录 B｜建议的一期数据切分

1. **无标注预训练集：** GeMS-A10 或同类公开谱；只学习谱图分布。
2. **有标签训练/验证集：** MoNA、MassBank 等；按结构簇切分。
3. **冻结计算测试集：** MassSpecGym 固定版本或双方另建外部标准谱面板。
4. **开放世界测试集：** 从候选池移除真值，并设置化学上相近的困难负例。
5. **盲标准品集：** 身份对建模团队隐藏，模型和阈值冻结后揭盲。
6. **真实外部应用集：** MTBLS13729 等；评价覆盖、稳定、拒答和后续验证效率，不虚构未知谱真值。

## 附录 C｜建议预注册的验收表

| 能力 | 主指标 | 最低保护条件 |
|---|---|---|
| 候选检索 | Hit@1 | Hit@5、MRR、MCES@1 不恶化 |
| 近异构体 | 分层 Hit@1 / MCES@1 | 不允许以总体提升掩盖明显退化 |
| 跨条件泛化 | 跨仪器/能量/实验室 Hit@k | 按结构配对统计 |
| 开放世界识别 | leave-truth-out AUROC/AUPRC | 高置信错误率和 FPR 必须受控 |
| 置信度 | ECE、Brier、risk–coverage | 报告覆盖率与拒答率 |
| 失败影响 | corrected / introduced | 新引入错误不得被均值隐藏 |
| 实验验证 | 盲标准品 Top-k 与 Level 1 命中率 | 预先冻结阈值和揭盲流程 |

## 附录 D｜A 教授可能追问的八个问题

### 1. 这个问题与一般分类有什么不同？

“类别不是固定且封闭的。化学空间巨大，许多真结构没有参考谱，甚至不在候选库中；同时同一结构会因实验条件产生不同观测。因此它同时包含反问题、跨域泛化和开放世界判断。”

### 2. 大算力最可能首先带来什么？

“最直接的是覆盖更多无标注谱、探索更多训练目标和困难负例，并系统化运行消融与反证。最终收益是否能进入结构检索和盲标准品，仍需由冻结协议判断。”

### 3. 为什么不把所有知识库一起喂给模型？

“知识库的证据层级不同。谱图真值、候选结构、通路关系和疾病关联不能当作同一种标签。先按角色分层，才能避免把相关性误当作结构身份。”

### 4. 没有标签的 2400 万张谱到底能学到什么？

“可以学习真实峰分布、共现、质量差、跨条件稳定性等表示，但能否对应到结构仍需带标签谱库和外部真值检验。无标注规模本身不是结构正确性的证据。”

### 5. 如果正确结构根本不在数据库里怎么办？

“这是必须单独评测的开放世界任务。系统应检测候选不完整，并退到结构家族、分子式或未知；评测中可以通过移除真值构造可控压力测试。”

### 6. 最终能否发现全新分子？

“可以把 de novo 结构生成作为中长期目标，但新分子发现还需要化学合理性、合成或分离、标准品谱和正交实验确认。第一期先建立候选检索和开放世界可靠性。”

### 7. 真实队列没有真值，如何证明有用？

“不在未知峰上虚构准确率。报告覆盖、重复稳定性、拒答、标准品验证优先级和最终验证命中率；真实性来自后续标准品或正交实验。”

### 8. 双方合作的最小可交付是什么？

“一份冻结 Task Card、一套公开数据与许可证台账、一套可复现基准、一个开放世界负对照和一个盲标准品计划。先让问题可运行、可否证，再扩展算力。”

# 五、可直接照读的开场与收尾

## 40 秒开场

“A 老师您好。我们今天想讨论的不是一套已经固定的算法，而是一个可能适合大规模 AI for Science 的科学问题。非靶向代谢组学能够测到大量分子信号，但多数串联质谱仍没有可靠的结构身份。我们希望把问题定义成一个可以直接进入计算研究、也可以被实验否证的任务：输入是什么，系统最终应该输出什么，以及在冻结基准、盲标准品和真实研究中怎样才算真正做对。我们也希望听听您的判断，这个问题是否适合由大规模 Agent 体系进行并行探索。”

## 55 秒收尾

“总结一下，我们提出的是一个开放世界、受物理约束的结构反演问题。候选存在时，系统要尽可能把正确结构排到前面；候选缺失或证据不足时，要能够退回到较低层级并拒答。公开数据已经提供亿级无标注谱图、十万级标准化有标签数据和真实研究队列；冻结检索、候选移除压力测试和盲标准品，又为它提供了明确的否证终点。我们建议第一步不先限定算法，也不先承诺大规模资源，而是双方共同冻结任务、数据权限和验收协议，再决定最值得投入 Agent 与算力的方向。”

# 六、五项严格审核结果

## 1. 场景适配审核：通过

### 审核问题

- 这是不是第一次与潜在合作方交流，而不是组内进展汇报？是。
- 对方是否主要需要判断问题价值和可计算性？是。
- 是否应该隐藏本组算法尝试和内部性能？是。

### 已落实的处理

- 主讲没有 ChemAware、BioAware、内部权重、失败路线或性能数字。
- DreaMS 只作为公开数据与基础模型范例，不作为本组成果。
- MTBLS13729 只作为真实外部压力测试，不把合作限定在该队列。
- 最后一页请求共同冻结一期任务，不要求当场承诺人员、算力或算法路线。
- 全场用“共同讨论、共同冻结、一期任务”表达合作，不给对方布置工作。

## 2. 语言合规性与得体性审核：通过

| 内部想法或不当表达 | 对外合规表达 |
|---|---|
| “叉院有算力但不知道做什么” | “叉院正在布局 AI for Science，我们希望共同筛选适合规模化推进的问题” |
| “用 Agent 暴力破拆” | “利用大规模 Agent 做并行假设生成、实验搜索和自动反证” |
| “我们把课题交给你们算” | “双方先共同冻结任务边界和评价，再讨论协作方式” |
| “模型把代谢物鉴定出来” | “模型给出结构候选；确认身份仍取决于证据等级” |
| “解决代谢组暗物质” | “提高未知谱图进入可验证候选范围的比例” |
| “海量数据一定能训练出答案” | “海量无标注数据提供表示学习机会，结构正确性仍需真值验证” |

### 数据合规边界

- 公开数据、需申请数据和商业授权数据必须分开。
- NIST 不能写成默认公开数据；KEGG 批量数据要注明许可边界。
- 患者队列即使公开，也应保留其数据许可、伦理和再利用条件说明。
- 不在首次交流中承诺可直接取得 UK Biobank 等受控人群数据。

## 3. 听众友好型审核：通过

- 前三页不出现模型架构和损失函数，先讲清“观测—反推—多解”。
- 术语首次出现即用一句白话解释：非靶向、MS/MS、候选池、开放世界、标准品。
- 数据库按五类角色组织，避免让 AI 听众记忆十几个缩写。
- 每页只有一个主判断，标题直接表达结论。
- 主讲只保留四组必要规模数字：GeMS、MoNA、MassSpecGym、MTBLS13729。
- 计算正确与化学确认用三级阶梯呈现，避免跨学科听众混淆。
- 预先准备八个追问答案，现场可短答，不需要临时展开内部算法。

## 4. 逻辑性审核：通过

完整逻辑链如下：

1. 大量代谢信号没有可靠身份，形成实际科学瓶颈；
2. 原因是谱图到结构属于多解、条件依赖、开放世界的反问题；
3. 因而一期任务必须区分候选池内检索和候选缺失判断；
4. 要运行任务，先明确输入记录和数据格式；
5. 不同数据承担无标注学习、真值对齐、候选生成、冻结评测和外部验证等不同角色；
6. 因为真实世界存在信息不足，输出必须包含置信度、证据、结论层级和拒答；
7. 因为计算检索不等于化学确认，评价必须分成计算、盲标准品和真实应用三层；
8. 只有在统一协议下，大规模 Agent 的并行搜索才会产生可比较、可否证的科学结论；
9. 因此合理的合作起点是共同冻结一期任务，而不是先争论某种算法。

任何不能推动这条链的信息都进入附录，不进入主讲。

## 5. 中文自然表达审核：通过

- 主讲使用“谱图、候选、结构、置信度、证据、确认、拒答”等自然科研表达。
- 删除“赋能、抓手、闭环、范式跃迁、全链条”等空泛词。
- 避免连续名词堆叠，例如不说“跨仪器谱图结构基础表征泛化能力”，改说“模型换一台仪器后还能不能认出同一结构”。
- 不反复使用“从……到……”标题，只有封面保留一次。
- 讲稿先说结论，再解释原因；单句尽量不超过两层从句。
- 不使用“破解、彻底解决、唯一确定”等超出证据的词。
- 对 A 教授统一使用“A 老师”或“A 教授”，不使用“姚期智下面的教授”等内部称呼。
