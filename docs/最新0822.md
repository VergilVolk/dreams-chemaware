结论先说：几个月的工作没有白费，但最近的实验确实被一个概念混淆带偏了。现在还不能宣布“噪声微调失败”，因为 P0 根本没有检验你们真正关心的谱峰噪声。

你们目前验证的是：

> 冻结的 Transformer 在 `train()` 状态下保留网络内部 dropout，会不会干扰线性头训练？

你们尚未严格验证的是：

> 删除、扰动或遮蔽特定谱峰，能否纠正 DreaMS 的具体检索错误？

这是本轮最重要的重新裁决。

## 一、P0究竟证明了什么

代码中 P0 的单变量开关位于 [step4_m1b_train.py](D:/DreaMS/tasks/step4_m1b_train.py:354)：

- `model.backbone.eval()`：关闭 Transformer 内部 dropout；
- `model.train()`：冻结的 backbone 仍产生随机表示。

所以 P0 比较的是“网络内部随机 dropout 开/关”，没有修改输入谱图，没有随机删峰，没有针对错误峰做反事实遮蔽。

因此正式结论只能是：

1. 发现了一个真实工程 bug：冻结 backbone 时必须保持 `eval()`。
2. 修复后 representation preservation 提高，margin 压缩消失。
3. 冻结 backbone＋线性投影头无法明显改善近异构体排序。
4. 谱峰噪声增强、定向峰遮蔽、因果噪声微调仍未得到有效检验。

DeepSeek把“head-only失败”进一步推导成“噪声路线结束”，这个判断越界了。

## 二、真正的根本问题

目前的困难来自四层错位。

### 1. 错误发生在峰级证据选择，训练却只旋转最终向量

当前 M1b 只训练约105万参数的投影头，116M参数的峰编码、注意力和Transformer全部冻结。

但你们要纠正的问题是：

- 模型过度依赖哪些共享主峰；
- 哪些条件特异峰应当忽略；
- 哪些弱峰能够区分异构体；
- 中性丢失和碎片组合如何参与判断。

这些信息在进入线性头之前就已经完成聚合。线性头只能改变全局度量，无法重新分配单个峰的贡献。

所以反复出现：

\[
\Delta s_{\text{positive}}>0,\qquad
\Delta s_{\text{hard negative}}>0
\]

正负一起抬升是架构位置错误的直接表现，不只是损失函数或学习率问题。

### 2. “噪声”被混成了三种不同操作

| 操作 | 目的 | 当前状态 |
|---|---|---|
| 网络内部 dropout | 常规正则化 | P0已测，冻结backbone时应关闭 |
| 随机删弱峰、强度抖动、添加低强度峰 | 提高一般鲁棒性 | 尚未在正确架构上严格验证 |
| 针对错误主峰、条件特异峰的反事实遮蔽 | 纠正已知错误机制 | 核心假设尚未正式验证 |

DreaMS预训练本来就随机遮蔽30%的m/z，而且按峰强度加权采样；简单随机遮蔽很可能重复其已有能力。[DreaMS论文](https://www.nature.com/articles/s41587-025-02663-3)

MS2DeepScore使用的低强度峰删除、强度抖动和低强度噪声峰，主要作用是一般正则化，并没有专门解决同分异构体局部排序。[MS2DeepScore](https://pmc.ncbi.nlm.nih.gov/articles/8556919/)

真正仍有创新空间的是第三类：基于真实失败案例定位峰，再进行定向反事实训练。

### 3. 优化目标仍未完全对应实际检索

MassSpecGym把检索定义为：

> 对每张查询谱图，在其真实候选集合中排列候选，评价Hit@k和MCES@1。

这天然是候选列表排序问题，不是全局pair分类，也不是随机triplet问题。[MassSpecGym](https://proceedings.neurips.cc/paper_files/paper/2024/file/c6c31413d5c53b7d1c343c1498734b0f-Paper-Datasets_and_Benchmarks_Track.pdf)

现在的训练仍有三个偏差：

- 每个query只用DreaMS最相似的同分子谱作为正例，相当于选择最容易的正例；
- 只推Top-5负例，无法覆盖完整候选结构；
- g8r开发评价的候选来自2000条子集，并非完整候选库。

因此，它更接近“子集内谱库身份检索”，不能直接等同于现实结构注释或MassSpecGym候选分子检索。

### 4. 单一cosine承担了互相冲突的任务

你们要求同一个全局embedding同时做到：

- 对仪器和碰撞能量变化保持不变；
- 对非常微小的异构体峰差保持敏感。

这两种目标天然存在张力。

DreaMS的precursor token将整张谱图聚合到一个向量中；共享高强度碎片容易主导全局方向，弱但关键的异构体峰容易被压缩。[DreaMS论文](https://www.nature.com/articles/s41587-025-02663-3)

部分异构体的MS/MS信息本身也不足以唯一确定结构。这类样本需要MS1、加合物、仪器、碰撞能量、保留时间或候选结构信息，单靠一个MS/MS余弦无法解决。

## 三、RAW reranker不是失败，反而揭示了最关键的科学事实

开发集结果：

\[
\mathrm{Recall@1}: 0.8081\rightarrow0.8516
\]

即使暂时不能当作最终成绩，它已经提示：

> 原始谱峰中存在能够纠正DreaMS错误的信息，但这些信息没有被充分保留在precursor embedding的单一cosine里。

这才是目前最有价值的发现。

MS2Query已经采用类似范式：第一阶段用embedding召回，第二阶段结合多种谱图与质量信息重排候选。[MS2Query](https://www.nature.com/articles/s41467-023-37446-4)

因此，reranker不是“退回传统算法”，它可以形成非常清楚的科学故事：

> DreaMS负责全局化学邻域召回，峰级证据模型负责近质量候选的局部判别，规则模块负责机理解释和置信度。

## 四、对当前RAW reranker代码的严格审核

### 做对的部分

- 在真实query候选组内构造正负差分；
- formula-group OOF选择正则化强度；
- gate阈值使用OOF预测，避免直接在训练拟合结果上选门；
- 训练和验证IK14隔离；
- 原始特征不依赖结构标签，部署时可计算；
- DreaMS候选与RAW峰匹配形成互补。

### 仍需修正的部分

1. **75.7%分子式重叠不等于增益主要来自seen-formula。**

   这是尚未验证的推测。必须等待seen/unseen分层，不能提前下结论。

2. **当前候选图只在g8r子集内部构建。**

   [train_g8r_raw_reranker.py](D:/DreaMS/tasks/train_g8r_raw_reranker.py:113)只在当前`entries`中寻找±10 ppm候选。最终测试必须使用完整参考库候选，否则任务难度和实际部署不一致。

3. **正例选择偏容易。**

   [train_g8r_raw_reranker.py](D:/DreaMS/tasks/train_g8r_raw_reranker.py:155)取DreaMS最相似的同分子正例。它优化的是“找到任意一张容易的同分子谱”，没有真正保护最困难的跨条件正例。

4. **固定0.02 Da峰匹配容差需要重审。**

   [train_g8r_raw_reranker.py](D:/DreaMS/tasks/train_g8r_raw_reranker.py:69)使用绝对0.02 Da。它在m/z=100时相当于200 ppm，在m/z=1000时相当于20 ppm。高分辨数据更适合混合容差或仪器相关容差。只能在训练OOF中确定一次，然后冻结。

5. **三seed结果并非三份独立外部证据。**

   它们共享相同开发样本。12/4也是跨seed累计转换，不能表述为12个不同错误被独立修正。

6. **46.5% gate覆盖率本身没有对错。**

   应绘制risk–coverage曲线，观察覆盖率增加时新增错误率如何变化。固定强调“门太宽”缺少依据。近期的可靠检索研究也强调每个谱图需要单独的置信度和候选集合校准。[JCIM 2026](https://pubs.acs.org/doi/abs/10.1021/acs.jcim.6c00727)

## 五、短期最大性能路线

### P0：立即停止继续烧预算的工作

暂时停止：

- 线性head的更多margin、λ、学习率扫描；
- 把网络dropout当作峰噪声研究；
- 规则Jaccard作为距离或正负标签；
- 在g8r_val上继续反复调整架构。

### P1：先把+4.35 pp查实

必须完成四项：

1. seen/unseen-formula、seen/unseen-scaffold；
2. near/mid与候选数量分层；
3. formula-cluster bootstrap CI；
4. DreaMS、RAW-only、DreaMS+RAW、无gate、gate五组消融。

并修正：

- 完整候选池；
- 峰匹配容差；
- 困难跨条件正例；
- 每个query按IK14等权。

若开发集仍保持至少+2 pp，立刻冻结模型、特征、容差、C和gate，一次性开启Test-A/Test-B。

建议通过门：

- Test-A Recall@1至少+2 pp，95% CI下界大于0；
- Test-B近异构体至少+3 pp；
- introduced/corrected不高于0.5；
- unseen-formula无显著退化；
- 任何仪器或CE亚组不得下降超过1 pp。

这条路线最可能最快得到真正更好的检索系统。

## 六、真正值得做的“精美微调”

下一版不要再训练全局线性head。采用：

### Candidate-aware peak ranker

\[
q \xrightarrow{\text{DreaMS}} \text{Top-K候选}
\xrightarrow{\text{峰级条件评分}} \text{最终排序}
\]

第二阶段直接读取：

- query与candidate的peak token；
- 碎片峰配对；
- 中性丢失配对；
- 仪器、碰撞能量和加合物；
- DreaMS全局相似度。

训练采用完整候选组上的listwise softmax，而不是独立triplet：

\[
L_{\mathrm{list}}
=-\log
\frac{\exp s(q,c^+)/\tau}
{\sum_{c\in C(q)}\exp s(q,c)/\tau}
\]

参数优先放在：

- 小型峰级attention/gating adapter；
- 最后一层Transformer的LoRA或adapter；
- 暂不全量解冻116M参数。

同时用官方模型的候选分布做保持：

\[
L_{\mathrm{preserve}}
=
D_{\mathrm{KL}}
\big(
P_{\mathrm{official}}(C|q)
\parallel
P_{\mathrm{new}}(C|q)
\big)
\]

这比约束两个embedding余弦更合理，因为它保护的是检索功能。

### 然后才加入真正的噪声实验

顺序必须是：

1. 无增强的peak-ranker基线；
2. 真实跨条件同分子正例；
3. 低强度峰删除、强度扰动；
4. 错误驱动的反事实峰遮蔽；
5. 分别消融，确认每种增强修正了什么错误、又引入了什么错误。

训练池使用现有完整E1池中约11.2万anchors，按IK14、分子式、仪器和CE平衡；每个query在线挖当前模型的Top-K困难负例。单纯把现有3434个hard anchor重复更多epoch不会解决覆盖问题。

## 七、规则库没有白费，但职责必须改变

原命题“规则决定embedding距离”已经失败，这一用途应当永久停止。

规则库仍能承担三项关键工作：

1. **候选重排特征**：具体碎片、中性丢失、同位素是否支持候选；
2. **化学概念监督**：检验embedding或peak token能否解码CF、NL、ISO等概念；
3. **解释与置信度**：说明某次改排由哪些峰和机理推动。

第一版只使用335条核心规则，并按支持度、稳定性和结构判别力在训练集内部筛选；3151条MassBank规则暂时保留为候选知识库，不能整体注入。

Task 0已经证明CF、ISO、NL类别信息量不同。这个结果正好支持“选择性概念分支”，不支持“3486维规则距离”。

## 最终裁决

你们没有得到更好的纯embedding，这是必须承认的。

但现在已经获得一个更重要、也更接近论文的问题定义：

> DreaMS的全局embedding擅长候选召回，但会压缩部分峰级局部判别信息；原始碎片与中性丢失证据能够恢复这些信息。

因此最短、最稳、最可能产生大提升的架构是：

\[
\boxed{
\text{DreaMS全局召回}
+
\text{候选组内峰级重排}
+
\text{规则解释与置信度}
}
\]

当前不要再围绕线性head和随机噪声继续兜圈。先验证+4.35 pp，随后把RAW重排器升级成可学习的峰级candidate-aware ranker；定向噪声作为这个模型的增强项重新进入。这样既能最快争取性能结果，也能保住化学感知与可解释性的核心科学故事。
