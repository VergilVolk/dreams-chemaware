**版本：** V3 场景适配终审版（2026-09-02）  
**适用场景：** 与 A 教授第一次正式交流；主讲 18–20 分钟，随后讨论 20–30 分钟  
**听众画像：** AI、Agent 和规模化计算背景强；不默认熟悉非靶向代谢组学、LC–MS/MS、加合物和鉴定等级

## 0. 全场唯一中心句

> **给定一张未知小分子的 MS/MS 谱图及其采集条件，能否输出证据可追溯、置信度可校准的分层结构结论；当正确结构不在候选库中或证据不足时，能否可靠地拒答？**

这句话必须在第 3 页正式说出，并贯穿后续三部分：

1. **输入是什么：** 谱图记录、候选空间，以及各类公开数据分别承担什么角色；
2. **最终目标是什么：** 不是对每张谱强制命名，而是输出候选、置信度、证据、结论层级和拒答；
3. **怎样算做对：** 计算检索、候选缺失、盲标准品和真实队列分层验收。

### 本场绝不使用的叙事

- 不说“叉院有很多算力但不知道做什么”；这既不适合交流场景，也会削弱科学问题本身的价值。
- 不说“请贵组用 Agent 暴力破拆”；改说“用规模化 Agent 并行提出、执行和反驳科学假设”。
- 不说“我们已有算法，只差算力”；本次只讨论任务定义、数据、目标和可否证标准。
- 不把 MTBLS13729 讲成课题本身；它只是一个真实应用压力测试。
- 不把“候选池 Top-1 正确”“谱库高相似”“真实样本中完成鉴定”混为同一层结论。

# 2. 逐页屏幕内容与可直接照讲的讲稿

## 第 1 页｜封面：把交流定位放对

### 屏幕标题

**从串联质谱到可信的代谢物结构结论**  
副标题：一个可规模化探索、也可被严格否证的 AI for Science 问题

页面下方只放汇报人、双方单位和日期。不要出现内部项目名、模型名、实验编号或性能数字。

### 视觉建议

左侧一张简洁 MS/MS 棒状谱，右侧放三个质量相近的候选结构，中间一个问号。视觉只表达：**看到碎片以后，原分子是谁？**

### 听众离开本页时只需记住

**今天讨论的是一个科学任务及其验收方式，不是来推销某条既定算法。**

### 可直接照讲

“A 老师您好。今天我们想讨论一个可能适合 AI for Science 规模化推进的科学问题：能不能从小分子的串联质谱出发，得到可信、可验证的结构结论。

这次我们先不预设算法路线，重点把三件事讲清楚：模型究竟拿到什么数据；最终应该交付什么；以及怎样才能严格说明它做对了。最后想请您一起判断，这个问题是否值得冻结成一个双方都能验证的一期任务。”

### 场景审核

- **得体：** 用“共同判断”“冻结任务”，不用“请贵组帮我们做”。
- **合规：** 不作能力承诺，不暗示对方必须投入资源。
- **中文：** “先不预设算法路线”比“我们不讲自己的算法尝试”更自然。

### 转场

“先看为什么这件事值得做：仪器已经测到了很多信号，但测到并不等于认出。”

## 第 2 页｜实际瓶颈：测得到，不等于认得出

### 屏幕标题

**非靶向代谢组学产生大量信号，但多数 MS/MS 仍没有可靠的结构身份**

### 屏幕只放三步

`生物样本 → LC–MS/MS → 大量峰和串联质谱`

然后突出一个断点：

`有观测 ≠ 有结构身份 → 难以进入通路解释、机制研究和标准品验证`

页脚可写：**DreaMS 论文的背景判断：典型非靶向实验中，现有方法通常只能为少于 10% 的小分子 MS/MS 分配结构。该比例是研究背景量级，不是所有平台的固定常数。**

### 听众离开本页时只需记住

**瓶颈不是没有质谱数据，而是大量观测无法转化为可验证的分子身份。**

### 可直接照讲

“非靶向代谢组学，可以先简单理解为：事先不限定分子清单，尽可能广泛地测量样本中的小分子信号。一次实验会产生大量峰和 MS/MS，但仪器记录的是离子的质量和碎裂结果，不会直接返回一个可靠的分子名称。

所以现在的矛盾不是没有数据，而是大量观测没有结构身份。没有身份，一个差异峰很难可靠地进入通路、机制或者后续实验。DreaMS 论文把这一背景概括为：典型非靶向实验中，能够被现有方法分配结构的小分子 MS/MS 通常不到 10%。这个数字只用来说明问题规模，不把它说成所有实验都一样。”

### 听众友好审核

- 第一次出现“非靶向”后立即用一句白话解释。
- 不在本页解释 Transformer、embedding 或碎裂规则；这些不是本页任务。
- 不用“代谢物识别率极低”这种含义不清的词，明确说“能够分配结构的谱图比例”。

### 转场

“这个问题之所以难，是因为我们看到的是碎裂后的部分观测，却要反推出碎裂前的结构。”

---

## 第 3 页｜科学问题：开放世界中的结构反演

### 屏幕标题

**从条件依赖、不完整的碎裂观测反推结构；正确答案还可能不在库中**

### 屏幕内容

左侧：

`母离子 → 碰撞碎裂 → 峰表 {(m/z, intensity)}`

右侧四个根本困难：

- **多解性：** 同质量、相近结构可能产生相似碎片；
- **条件依赖：** 仪器、碰撞能量、离子模式和加合物会改变谱图；
- **真值稀缺：** 亿级公共谱图中，可靠结构标签只覆盖少量数据；
- **开放世界：** 真分子可能没有参考谱，甚至不在候选库中。

页面中央放正式问题：

> **给定未知小分子 MS/MS 及采集条件，候选存在时能否找回正确结构；候选缺失或证据不足时，能否退回到分子式、结构家族或未知，并给出可校准的不确定性？**

### 听众离开本页时只需记住

**这不是普通封闭分类，而是带物理约束、候选缺失和拒答要求的反问题。**

### 可直接照讲

“MS/MS 可以理解为一次受控的分子破碎实验。仪器先选出一个母离子，让它碰撞碎裂，再记录每个碎片的质荷比和相对强度。模型看到的不是结构本身，而是结构在特定实验条件下留下的一组不完整观测。

这个反演不是一一对应。不同异构体可能共享很多碎片；同一个分子换仪器或碰撞能量，谱图也会变化。更现实的是，真正的分子可能从来没有被标准品测过，因此既没有参考谱，也可能不在候选库里。

因此我们把科学问题分成两层：候选存在时，尽量把真结构排到前面；候选不存在或证据不够时，系统必须知道自己不知道，退到分子式、结构家族或未知，而不是从错误候选中强行选一个。”

### 语言红线

- 不说“MS/MS 是分子的唯一指纹”；改为“条件依赖的碎裂观测”。
- 不说“一张谱恢复唯一完整结构”；改为“在证据允许范围内给出分层结论”。
- 不说“模型足够大就能解决异构体”；算力不能消除信息不可辨识性。

### 转场

“为了让这个问题能够被不同团队共同执行，下一页把一期任务冻结成一张任务卡。”

## 第 4 页｜一期任务卡：先让问题可比较、可否证

### 屏幕标题

**一期先冻结候选检索与拒答：同一输入、同一候选、同一真值、同一评价**

### 屏幕表格

| 要素 | 一期定义 |
|---|---|
| 输入 | 标准化 MS/MS 峰表 + precursor m/z + 离子模式/加合物 + 可得实验条件 |
| 候选 | 由精确质量或已知分子式，在固定版本结构库中产生的候选集合 |
| 输出 | Top-k 结构 + 校准置信度 + 支持/冲突证据 + 拒答状态 |
| 真值 | 已知结构的冻结测试谱；另加“移除真值”的候选缺失压力测试 |
| 边界 | 一期不要求从整个化学空间一步生成唯一结构 |

### 听众离开本页时只需记住

**一期不是缩小科学问题，而是先建立一个任何方案都必须通过的公共裁判。**

### 可直接照讲

“如果双方推进，我们建议先冻结一个足够清楚的一期任务。输入是一张标准化谱图和必要的采集上下文；候选由固定版本结构库按质量或分子式产生；输出不只是第一名，而是 Top-k、置信度、证据和是否拒答。

真值来自身份已知、结构冻结的参考谱。除此之外，我们还要人为把正确结构从候选池中移除，观察系统会不会仍然高置信地选错。这一步直接测试开放世界可靠性。

一期先不要求从整个化学空间一步生成唯一结构，是为了让不同模型、不同 Agent 路线能够在同一条件下接受比较。基础协议成立后，再扩展到分子式推断、结构生成和实验闭环。”

### 可能追问：为什么不直接做 de novo 结构生成？

“它可以作为并行前沿支线。但完整结构精确命中极难，等价结构处理和实验确认也更复杂。先用固定候选建立可靠基准，能更快判断规模化搜索带来的增益是否真实。”

### 转场

“任务卡中的第一项是输入。下面把一条标准记录具体展开。”

---

## 第 5 页｜标准输入：模型拿到的是数值峰表，不是谱图图片

### 屏幕标题

**最小输入是峰表和母离子信息；实验上下文决定跨平台泛化**

### 屏幕示例

```text
spectrum_id
peaks = [(m/z_1, intensity_1), ..., (m/z_n, intensity_n)]
precursor_mz
ion_mode / charge / adduct
collision_energy / instrument_type      # 如有
retention_time / chromatography         # 如有
sample_id / study_id                     # 真实队列中保留
```

格式链路：

`厂商 RAW → mzML/mzXML → MGF/MSP/JSON → 清洗后的 HDF5/张量`

实验设计与样本关系另存为：`ISA-Tab / TSV / JSON metadata`

### 听众离开本页时只需记住

**峰表是核心观测；格式转换不能丢失母离子、加合物、仪器条件和样本映射。**

### 可直接照讲

“对模型而言，一张谱不是图片，而是一组峰。每个峰由质荷比和相对强度组成，同时至少要知道母离子的质荷比。电离模式、电荷和加合物影响观测质量如何对应到中性分子；碰撞能量和仪器类型会改变碎裂；保留时间和色谱条件则提供额外证据。

仪器输出通常是厂商专有 RAW。公共交换格式常见 mzML、mzXML；单张谱或谱库交换常见 MGF、MSP 和 JSON。大规模训练时可以整理成 HDF5 或张量，但必须保留原始文件映射、转换版本和元数据缺失情况。

因此，数据标准化不是简单转格式。哪些字段必须保留、怎样去除空谱和污染谱、重复谱如何处理，本身就是一期任务的一部分。”

### 语言审核

- 不说“mzML 就是模型输入”；它是开放交换格式，进入训练前通常还会清洗和张量化。
- 不把固定峰数或 token 数写成科学问题的唯一输入；那只是具体实现选择。
- 对可能缺失的 retention time、collision energy 明确标“如有”。

### 转场

“知道一条记录长什么样以后，还要分清不同数据库在整个任务中分别做什么。”

## 第 6 页｜数据全景：五类资源不能按一个优先级混排

### 屏幕标题

**预训练语料、参考谱库、候选普库、冻结基准和真实队列承担不同职责**

### 屏幕内容

| 数据角色 | 回答的问题 | 代表资源 |
|---|---|---|
| 无标注谱图语料 | 真实谱图通常长什么样 | MassIVE-GNPS / GeMS-A10 |
| 带结构参考谱库 | 哪些谱对应哪些已知结构 | MoNA、MassBank；有授权时补 NIST |
| 候选结构普库 | 哪些结构在质量或分子式上可能成立 | PubChem、HMDB |
| 冻结计算基准 | 模型之间怎样公平比较 | MassSpecGym |
| 盲标准品与真实队列 | 离开题库后是否仍然可靠、可用 | 独立标准品面板、MetaboLights 研究 |

页脚：**KEGG、MetaCyc、BRENDA 等适合后续反应、通路和酶约束，不是 MS/MS 结构身份的主要真值来源。**

### 听众离开本页时只需记住

**“库里有结构”“库里有谱”“谱有真值”“数据可用于训练”是四件不同的事。**

### 可直接照讲

“这五类数据不能放在一张表里简单排优先级，因为它们回答的是不同问题。MassIVE 和 GeMS 规模大，但绝大多数没有结构标签，适合学习真实谱图分布。MoNA 和 MassBank 提供谱图—结构配对，适合监督对齐和参考检索。PubChem、HMDB 主要定义候选结构空间；一个结构被数据库收录，并不等于它有实验 MS/MS。

MassSpecGym 负责冻结切分、候选和指标。盲标准品和真实队列则检验模型离开公共题库以后是否还能工作。

KEGG、MetaCyc、BRENDA 很重要，但它们提供的是反应、通路、酶和生化背景，不能替代谱图—结构真值。”

### 场景审核

不要说“MOA 大于 MoNA、MassIVE”或“HMDB 比 MassSpecGym 更重要”。应说：**不同阶段使用不同数据，角色不能互相替代。**

### 转场

“先看最能体现规模化计算价值的一类：海量无标注谱图。”

## 第 7 页｜DreaMS/GeMS：无标注预训练语料从哪里来

### 屏幕标题

**DreaMS 从公共 MassIVE-GNPS 仓库整理 GeMS，并在约 2352 万张 GeMS-A10 谱上预训练**

### 屏幕只放四项

- **来源：** DreaMS 作者整理的 2022 年 11 月 MassIVE-GNPS 快照；
- **原始规模：** 约 24.9 万个含 MS/MS 的 LC–MS 文件、约 7.14 亿张清洗后 MS/MS；
- **实际预训练集：** GeMS-A10，`23,517,534` 张无结构标签谱；
- **格式与体量：** 公开 HDF5；压缩文件约 `14 GB`，未压缩约 `47 GB`。

小字口径：GeMS-A10 中“A”表示质量筛选层级，“10”表示每个相似谱簇最多保留 10 张；它不是 7.14 亿张 GeMS 的同义词。

### 听众离开本页时只需记住

**DreaMS 的训练价值来自高质量、多来源、去冗余的无标注语料，不是简单把所有公开谱都堆进去。**

### 可直接照讲

“DreaMS 的数据工作说明，公共质谱仓库已经达到基础模型规模。作者从 MassIVE-GNPS 的快照中整理出 GeMS：约 24.9 万个包含 MS/MS 的文件，清洗后约 7.14 亿张谱。

但真正用于 DreaMS 预训练的不是全部 7.14 亿张，而是质量筛选并限制相似谱重复后的 GeMS-A10，共 23,517,534 张。官方 HDF5 压缩文件约 14 GB，未压缩约 47 GB。这些谱绝大多数没有结构标签，模型通过遮蔽峰重建和保留顺序等自监督任务学习谱图表示。

这里最值得带走的不是一个更大的数字，而是：规模、质量、重复度和实验分布必须一起设计。算力可以扩大训练和实验搜索，但数据治理决定它学到的是化学规律还是仓库偏差。”

### 数字口径审核

- `714 million`：清洗后的完整 GeMS；
- `23.52 million`：DreaMS 实际使用的 GeMS-A10；
- `201 million`：DreaMS Atlas 覆盖的另一套 GeMS-C 规模；
- 三者绝不能都称为“DreaMS 训练集”。

### 转场

“无标注语料帮助学习表示，但结构对齐、候选检索和公平评测还需要另外三类资源。”

## 第 8 页｜MoNA、普库与 MassSpecGym：标签、候选和裁判分开讲

### 屏幕标题

**带标签谱库提供结构配对，候选普库定义搜索空间，基准负责公平验收**

### 屏幕三列

#### 1. MoNA：带结构参考谱库

- 建设方：UC Davis Fiehn Lab 维护的 MassBank of North America；
- 内容：实验/计算谱、结构标识符、precursor/adduct、仪器与碰撞条件；
- 格式：JSON、MSP、SDF；
- **DreaMS 特定划分：** 训练 `25,319` 谱 / `5,524` 分子；验证 `3,557` 谱 / `831` 分子；合计约 `2.9 万谱 / 6,355 分子`。

#### 2. PubChem / HMDB：候选结构与属性

- PubChem 由 NCBI 维护；HMDB 由 University of Alberta 团队建设；
- 内容：分子式、精确质量、SMILES、InChI/InChIKey 及理化/生物信息；
- 格式：SDF、SMILES、XML、JSON、CSV；
- 作用：按质量或分子式生成候选；**不等同于有实验参考谱。**

#### 3. MassSpecGym：冻结计算基准

- 约 `231,104` 张标准化正离子 MS/MS，约 `29k` 个独特结构；
- 谱来源：MoNA、MassBank、GNPS 及作者组内数据；
- 候选：10 ppm 质量候选或同分子式候选，最多 `256` 个；
- 切分：按 MCES 结构距离分组，减少相近结构跨集合泄漏。

### 听众离开本页时只需记住

**MoNA 是“带答案的题”，PubChem/HMDB 是“备选答案空间”，MassSpecGym 是“统一考试规则”。**

### 可直接照讲

“这三类资源最容易混淆。MoNA 提供带结构标签的参考谱。DreaMS 论文用于谱图相似度微调的特定 MoNA 划分，训练和验证合计约 2.9 万张谱、6355 个分子。这个数字只代表论文当时的清洗和切分，不代表 MoNA 官网当前全库规模；官网还混合不同来源的实验谱和计算谱，必须按任务重新筛选。

PubChem 和 HMDB 主要提供候选结构与属性。它们可以按精确质量或分子式生成候选，但结构被收录不等于已经有实验谱。

MassSpecGym 则是统一考试。它整理约 23.1 万张正离子 MS/MS、约 2.9 万个独特结构；候选最多 256 个，并用结构距离隔离训练和测试。这使 AI 团队可以在不先掌握全部质谱工程细节的情况下，对同一任务做可复现比较。”

### 事实和合规审核

- MoNA 当前页面规模会更新，主讲只报 **DreaMS 特定划分**，并显式标注口径。
- NIST 是重要高质量授权谱库；没有双方明确许可时，只说“有授权时可作为外部补充”，不把它列为默认公开数据。
- MassSpecGym 当前主基准聚焦正离子、常见加合物和单电荷谱；不能用其成绩代替负离子或复杂真实样本评价。

### 转场

“计算基准解决有答案的题；真实队列则检验整个流程离开题库后是否还能工作。”

## 第 9 页｜真实队列：MTBLS13729 只承担压力测试角色

### 屏幕标题

**真实队列检验流程可用性并产生待验证候选，但不能提供全部未知峰的结构真值**

### 屏幕内容

**数据事实**

- MetaboLights 公开研究；由 EMBL–EBI 托管，许可为 CC0 1.0；
- 30 位结直肠癌患者，肿瘤与配对正常组织，共 60 个样本；
- HILIC / RPLC × 正 / 负离子，共 4 个 LC–MS 面板；
- 每个面板 60 条 assay 记录，共 240 条；公开文件为 mzML，并配套 ISA-Tab/assay metadata。

**它可以回答**

1. 从 mzML 到候选结论的完整流程能否运行；
2. 跨色谱、离子模式和真实组织样本是否稳定；
3. 哪些候选最值得购买标准品或做靶向验证。

**它不能直接回答**

- 所有未知峰的 Top-1 准确率；
- 一个差异峰的结构是否已经确认；
- 静态丰度变化是否等于代谢通量或酶活改变。

### 听众离开本页时只需记住

**MTBLS13729 是应用压力测试和实验入口，不是模型训练唯一目标，也不是逐谱真值集。**

### 可直接照讲

“我们可以用 MTBLS13729 说明真实应用场景，但不把课题限定在这个数据集。它由 MetaboLights 公开托管，包含 30 位结直肠癌患者的肿瘤和配对正常组织，共 60 个样本；HILIC、反相色谱和正负离子组合成四个面板，因此一共有 240 条 assay 记录，并配有 mzML 和 ISA-Tab 元数据。

这类数据适合检验从公开文件、谱图提取、候选排序到后续实验决策的完整流程，也能筛选最值得购买标准品的候选。

但大量未知峰没有逐一结构真值，所以不能在这个队列上直接声称‘全部未知谱 Top-1 准确率提高’，更不能把差异丰度当成身份真值。真实队列的价值，是把模型输出送进可验证的实验闭环。”

### 场景与内容审核

- 主讲不展示本组在该队列上的具体候选、显著性或内部模型提升。
- 不把公开 mzML 称为厂商原始 RAW。
- 不把论文作者已有的代谢物鉴定全部算作模型新发现。

### 转场

“输入和数据边界明确以后，下面回答第二个核心问题：系统最终到底要交付什么。”

## 第 10 页｜最终目标：可靠结论，而不是强制命名

### 屏幕标题

**最终输出是候选、置信度、证据、结论层级和拒答，不只是一个名称**

### 屏幕五项输出

1. **候选排序：** Top-k 结构、分子式、SMILES/InChIKey；
2. **校准置信度：** 同等置信度结果中，实际正确比例应与分值匹配；
3. **支持证据：** 支持候选的碎片、质量约束和实验条件；
4. **冲突与缺失：** 不匹配峰、条件冲突、候选库可能不完整；
5. **结论层级：** 完整结构候选、结构家族、分子式或未知，并允许拒答。

页面底部：

> **候选存在时尽量找回真结构；候选缺失或证据不足时，不制造虚假的确定性。**

### 听众离开本页时只需记住

**高质量系统既要会答题，也要知道何时不应回答。**

### 可直接照讲

“如果把最终目标只写成‘输出一个代谢物名称’，模型很容易在每张谱上强行猜测。我们希望系统至少交付五类信息：Top-k 候选；经过校准的置信度；支持候选的峰和质量证据；与候选冲突的证据；以及结论能够具体到哪一层。

证据充分时可以给完整结构候选；证据不足时，应退到结构家族、分子式或者未知。这里的置信度也不能只是网络内部一个分数，而要能回答：在系统给出相同置信度的一批结果中，实际有多少最终被真值验证。

拒答不是失败，而是科学可靠性的一部分。一个系统如果少回答一些，却显著减少高置信错误，可能比给所有谱都填上名称更有价值。”

### 可能追问：追求覆盖率还是准确率？

“二者必须一起报告。用 risk–coverage 或 accuracy–coverage 曲线表示：在不同拒答阈值下，系统覆盖多少谱，保留下来的答案有多可靠。实际阈值由标准品和后续实验成本决定。”

### 转场

“最终目标明确以后，第三个核心问题是：怎样证明模型真的变强，而不是换了数据、候选或评价口径。”

---

## 第 11 页｜第一层验收：模型能力是否真的增强

### 屏幕标题

**只有 query、候选池、切分和预处理全部相同，模型间的变化才可比较**

### 屏幕上半部：冻结协议

- 按完整分子身份或结构簇切分；同一分子的重复谱不能跨训练和测试；
- 锁定候选库版本、质量窗口、分子式条件和真值包含规则；
- 锁定输入预处理、谱图聚合、并列排名和缺失字段处理；
- 超参数只在训练/验证集选择，冻结测试集最后运行一次；
- 统计单位优先按分子或结构簇，避免重复谱虚增样本量。

### 屏幕下半部：四类指标

1. **排序：** Hit/Recall@1、@5、@20，MRR；
2. **结构接近：** MCES@1、指纹相似度；
3. **困难分层：** 近异构体、跨仪器、跨碰撞能量、低质量谱、低频结构；
4. **可靠性：** Brier/ECE、risk–coverage/AURC、拒答率、corrected/introduced。

另加一个开放世界测试：**移除正确候选后，统计高置信误接纳率和未知检出能力。**

### 听众离开本页时只需记住

**平均 Top-1 提高不是充分证据；必须同时证明无泄漏、困难样本不退化、置信度可信且新错可控。**

### 可直接照讲

“模型能力是否增强，首先要在有结构真值的冻结基准上判断。最重要的不是挑一个漂亮指标，而是先把比较协议锁死。

训练、验证和测试要按分子身份或更严格的结构簇隔离；同一分子的不同谱不能跨集合。候选库版本、质量窗口、谱图预处理和并列规则全部固定。测试集只在模型和阈值冻结以后运行。

指标上，Top-1 看第一名是否正确，Top-5 和 Top-20 看能否缩小实验范围，MRR 看整体排名。即使没有精确命中，也要看第一名离真结构有多远。平均结果之外，还要单列近异构体、跨仪器和跨碰撞能量等困难子集。

可靠性方面，要同时报告校准和拒答曲线，并统计纠正了多少旧错误、又引入多少新错误。最后把真值从候选池移除，检验系统能否识别‘答案不在这里’。只有这些条件同时成立，才可以说模型能力真的增强。”

### 比较纪律

**不同数据集、不同 query、不同候选规则下的百分点不能相加，也不能直接据此宣布模型优劣。**

### 可能追问：一期主指标是什么？

“建议预注册 Hit@1 为主指标，Hit@5、MRR、MCES@1 和 AURC 为共同次指标；近异构体、跨条件和高置信误接纳率设置不退化门槛。统计上采用 query 配对差异和置信区间，而不是只报一个点估计。”

### 转场

“计算基准能证明模型会不会做有答案的题，但还不能证明真实样本里的化学身份已经确认。”

---

## 第 12 页｜第二、三层验收：从计算正确到化学确认

### 屏幕标题

**候选检索第一不等于身份确认；真正的验证要经过盲标准品和真实外部应用**

### 屏幕三级阶梯

#### A. 封闭计算真值

已知谱 + 已知正确结构 + 固定候选池。  
可说：**检索正确、排名提高、结构更接近真值。**

#### B. 盲标准品与跨条件测试

模型冻结后揭盲；真实标准品在相同分析条件下测量，并加入跨仪器、跨碰撞能量或跨实验室复测。  
检查：Top-k、校准、RT 与 MS/MS 一致性、跨条件稳健性。  
可说：**标准品确认、外部泛化成立。**

#### C. 真实研究队列

报告覆盖率、拒答率、重复稳定性、送验候选数和标准品验证命中率。  
没有本实验标准品时，只说：**结构注释、Level 2 候选或待验证候选。**

### 听众离开本页时只需记住

**模型的价值是把实验验证空间显著缩小，而不是用计算分数替代化学真值。**

### 可直接照讲

“这一页决定我们最后能使用什么语言。冻结候选池中的 Top-1 正确，只说明模型在给定候选中找到了已知真值，不能自动等于真实样本中的化学身份确认。

更强的验证是盲标准品面板。模型和阈值冻结以后再揭盲，并尽可能在不同仪器、碰撞能量或实验室重复采集，检验表示是否真正跨条件迁移。

按照代谢组学报告规范，保守的 Level 1 需要真实标准品在相同分析条件下测量，并比较至少两类独立、正交的性质。实际 LC–MS 设计中可核对保留时间和 MS/MS，准确质量作为必要支持。只有公共谱库匹配而没有本实验标准品时，通常应称为 Level 2 的概率性结构注释。

真实队列用于检验流程是否可用：系统覆盖多少、拒答多少、重复是否稳定，以及送去做标准品验证的候选有多少最终命中。计算模型负责缩小验证空间，不负责取消实验真值。”

### 现场语言对照

| 实际证据 | 可以说 | 不可以说 |
|---|---|---|
| 固定候选池 Top-1 正确 | 检索正确、排名第一 | 已在真实样本中鉴定该代谢物 |
| 公共谱库高相似 | 高置信结构注释、Level 2 候选 | 唯一结构已经确认 |
| 精确质量/分子式一致 | 分子式候选、结构家族候选 | 已确定具体异构体 |
| 同条件标准品 + 正交性质一致 | Level 1 确认 | 由此直接证明代谢通量或具体酶机制 |

### 转场

“当输入、输出和验收标准都明确以后，这个问题才真正适合交给规模化 Agent 体系。”

---

## 第 13 页｜合作接口：让规模化搜索服从统一真值

### 屏幕标题

**这个问题适合规模化 Agent，因为假设空间大，而且每条路线都能被统一协议验证或否定**

### 左侧：为什么适合规模化 Agent

- **数据规模充足：** 千万级无标注预训练语料，十万级标准化有标签谱；
- **任务可以拆分：** 数据质控、表示学习、候选生成、碎裂推理、结构生成、校准和拒答；
- **假设空间很大：** 可并行探索数据配方、训练目标、化学约束和失败机制；
- **可以自动反驳：** 所有路线回到同一冻结基准、负对照和盲标准品；
- **能接实验终点：** 高价值候选进入标准品、靶向采集和跨实验室复测。

### 右侧：建议一期共同产物

1. 一份冻结的 **Task Card**；
2. 一份公开数据、版本、许可证和下载格式台账；
3. 一个结构隔离的候选检索基准；
4. 一个候选移除的开放世界压力测试；
5. 一个独立盲标准品面板；
6. 一套记录假设、实验、负结果和复现信息的 Agent 审计规范。

页面底部只留一个讨论问题：

> **双方是否先共同冻结一期任务与验收标准，再决定最值得投入规模化计算的研究分支？**

### 听众离开本页时只需记住

**双方第一步不是选算法，而是共同建立一个能支撑大规模探索、又不会被搜索本身污染的科学裁判。**

### 可直接照讲

“我们认为这个问题适合规模化 Agent，不只是因为谱图数量大。更重要的是，它可以拆成很多相对独立的科学假设，而每个假设都能回到同一套真值协议接受验证。

Agent 可以并行处理数据质控、表示学习、碎裂约束、候选检索、结构生成和置信度校准，也可以主动寻找失败案例、构造负对照和复现实验。但规模化搜索必须受统一评测约束，否则只会扩大试错数量，不能形成可信结论。

所以我们建议第一步不先指定算法，也不在今天讨论投入多少算力。更稳妥的是双方先共同冻结任务卡、数据与许可台账、结构隔离基准、候选移除测试和盲标准品面板。协议稳定后，再让不同 Agent 在同一边界内并行探索，才容易判断哪些提升是真实的。

想请您判断：这个问题是否值得作为一期 AI for Science 任务？如果值得，您认为最有价值的切入口是表示学习、结构推理，还是可靠性和自动验证？”

### 收尾语气

说完即停，进入讨论。不要再追加本组算法历史。若 A 教授主动问“你们已有何基础”，只回答数据准备、任务理解和实验验证能力，不主动展开内部试错路线。

1. **无标注预训练集：** GeMS-A10 或同类公共谱，只学习谱图分布；
2. **有标签训练/验证集：** MoNA、MassBank 等，按分子身份或结构簇隔离；
3. **封闭测试集：** query、候选和真值全部冻结；
4. **开放世界测试集：** 从候选池中移除真值，另设真正库外结构；
5. **盲标准品集：** 模型、阈值和候选规则冻结后揭盲；
6. **真实应用集：** 仅用于流程稳定性、候选筛选和后续验证，不反向调参。

## 附录 C｜预注册验收表

| 能力 | 主指标 | 最低安全门 |
|---|---|---|
| 封闭候选排序 | Hit@1 | 配对置信区间支持增益 |
| 缩小实验范围 | Hit@5、Hit@20、MRR | 不以 Top-1 换取严重整体退化 |
| 结构接近性 | MCES@1 | 未精确命中时仍更接近真值 |
| 困难候选 | near-isomer Hit@1 | 不低于冻结基线 |
| 开放世界 | 高置信误接纳率、未知检出率 | 候选移除后能明显降置信或拒答 |
| 校准与拒答 | Brier/ECE、AURC | 覆盖率下降时风险应单调降低 |
| 外部泛化 | 盲标准品 Top-k、RT/MS/MS 一致 | 阈值不可在盲集上选择 |
| 真实应用 | 覆盖率、拒答率、送验命中率 | 无标准品时不得宣称身份确认 |

# 5. 五项严格审核结论

## 5.1 场景适配审核：通过

- 开场把本次定位为“共同定义任务”，不是“算法汇报”“算力申请”或“工作外包”。
- 全场不出现本组内部模型名、实验结果、性能数字和试错史。
- 对 A 教授的邀请是“共同判断切入口”，不是把算法责任推给对方。
- 结尾提出一个可讨论的合作接口，不要求现场承诺资源。

## 5.2 语言合规性与得体性审核：通过

- 删除“暴力破拆”“不知道作甚”等不宜进入正式交流的表达。
- 所有数据库均按公开/授权属性表述；NIST 明确为授权资源。
- 对真实患者数据只陈述公开研究事实，不展示本组未经请求的内部结果。
- 对科学结论统一使用“检索、注释、候选、确认”四级词汇，不越级。

## 5.3 听众友好型审核：通过

- 第一次出现非靶向、MS/MS、加合物、开放世界时均给出直白解释。
- 每页设置“一句话记忆点”，避免听众被数据库数字淹没。
- 数据页采用“角色—来源—格式—规模—边界”，不做数据库名堆砌。
- 只在附录保留完整台账，主讲控制在 GeMS、MoNA、MassSpecGym、MTBLS13729 四组必要规模。

## 5.4 逻辑性审核：通过

全场因果链为：

`现实瓶颈 → 严格科学问题 → 一期任务卡 → 标准输入 → 数据角色 → 最终输出 → 分层验收 → Agent 合作接口`

其中：

- 第 3 页提出问题；
- 第 4 页把问题变成可执行任务；
- 第 5–9 页回答“输入和数据”；
- 第 10 页回答“最终目标”；
- 第 11–12 页回答“怎样算做对”；
- 第 13 页只在前述边界成立后讨论规模化 Agent。

不存在从“数据很多”直接跳到“需要大算力”的逻辑断裂。

## 5.5 中文自然表达审核：通过

- 讲稿以短句和主动句为主，减少“进行……的构建”“实现……的提升”等名词化表达。
- 用“先冻结任务，再选算法”替代生硬的“task formalization before method selection”。
- 用“系统必须知道自己不知道”解释拒答，但全场只出现一次，避免口号化。
- 每页转场回答“上一页留下的问题”，不使用机械的“接下来我们看”。
