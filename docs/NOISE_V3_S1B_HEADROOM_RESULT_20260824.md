# Noise-v3 S1b 动作互补性与理论上限

日期：2026-08-24  
作业：2323843  
状态：`noise_v3_s1b_action_headroom_complete`

## 主要结果

- 完整查询：23,876；
- 官方错误：1,805，Recall@1 = 0.92440；
- 非对照动作至少可修正的独立错误：386；
- no-op-aware oracle Recall@1 = 0.94057；
- 理论最大增益：+0.01617，即 **+1.62 pp**；
- near 错误 1,446 个，其中可修正 329 个，占 22.75%。

该 oracle 使用动作真实结果选择动作，因此只是动作空间上限，不是模型结果。

## 两条有效方向的互补性

| 错误集合 | 独立错误数 | 占全部官方错误 |
|---|---:|---:|
| candidate-gradient 可修正 | 352 | 19.50% |
| role-confounder 可修正 | 104 | 5.76% |
| 两者共同 | 70 | 3.88% |
| candidate-gradient 独有 | 282 | 15.62% |
| role-confounder 独有 | 34 | 1.88% |
| 任一非对照动作可修正 | 386 | 21.39% |

这说明 role-confounder 不是 candidate-gradient 的简单弱版本；它提供34个独有修正，并在安全性上明显更好。

## 性能目标边界

| 目标 | 所需净修正 | 当前动作 oracle 是否覆盖 |
|---|---:|---|
| +0.5 pp | 120 | 是 |
| +1.0 pp | 239 | 是 |
| +2.0 pp | 478 | 否 |
| +4.0 pp | 956 | 否 |

因此，当前动作空间足以支持“争取约1个百分点”的正式微调，但在数学上不能支持2–4个百分点的承诺。若目标仍是2个百分点以上，必须先扩展动作空间。

## 策略数据规模

- query-action 行：192,296；
- 至少一个非对照动作能够纠正的 query：386；
- 正向 action 行：864；
- 有害 action 行：1,771。

大量 action 行并不等于大量独立正样本。有效正例只有386个 query，直接训练高容量 DeepSets/Set Transformer 风险过高。

## 裁决

1. 通过“策略设计”门：动作空间超过1个百分点，两个选择器存在独有修正；
2. 未通过“高容量策略训练”数据门：正向 action 行不足1,000，独立正 query 仅386；
3. 下一步先扩展每个 query 的可选峰与组合动作，再训练非线性策略；
4. 第一版扩展应使用 top-k candidate-gradient 单峰、top-k role-confounder 单峰及最多三步顺序动作；
5. 继续保留 no-op，且正确样本安全性必须作为显式代价；
6. 化学规则只能作为策略特征做 with/without-rules 消融，不能定义正负动作标签。

当前成果的准确表述：已经证明 DreaMS 错误中存在可定位、方向相反且互补的峰级动作，但现有单峰动作空间的理论性能上限约为 +1.62 pp，尚不足以支持更高性能目标。
