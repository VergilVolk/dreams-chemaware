## 贯穿全场的核心科学问题

> **能否从一张在特定实验条件下获得的串联质谱中，推断产生它的代谢物结构；在相同质量、近异构体、跨仪器和库外分子等困难条件下，仍给出可校准、可验证、必要时能够拒答的结果？**

这不是普通分类。它是一个“从碎裂观测反推分子结构”的受物理约束反问题：观测不完整、结构空间巨大、不同结构可能产生相似碎片，同一结构也会因仪器和碰撞条件而产生不同谱图。

我们会尽量把问题讲成一个可以直接进入计算研究的任务：第一，输入数据具体是什么；第二，最终希望系统输出什么；第三，怎样严格判断它做对了。最后再说明，为什么这个问题可能适合贵组的大规模 Agent 和算力能力。”

## 第 2 页｜我们测到了大量信号，却不知道它们分别是什么

### 页面标题

**非靶向代谢组学的主要缺口，不是没有信号，而是大量谱图没有可靠结构身份**

### 页面内容

左侧：样本 → LC–MS/MS → 大量谱峰。  
右侧：少量“已注释”谱图 + 大量“未知”谱图。  
底部一句话：**没有结构身份，差异峰很难进入通路、机制和后续实验。**

可用一项公开事实作为量级提示：DreaMS 论文指出，现有方法通常只能给不到 10% 的小分子 MS/MS 谱图分配结构。不要把这个比例讲成所有平台、所有样本的固定定律。

### 讲稿

“非靶向代谢组学一次实验可以产生大量信号。仪器告诉我们某个离子有多重、在碰撞后产生了哪些碎片，但通常不会直接告诉我们它是哪一个分子。

真正的瓶颈是：我们已经看见了大量变化，却不知道这些变化对应什么化学实体。没有结构身份，一个差异峰很难进入通路分析、作用机制或后续标准品验证。公开研究普遍把这部分称为代谢组学的‘暗物质’。这里的价值不是把一个表格填满，而是让原本不可解释的实验信号进入可验证的生物学研究。”

### 听众友好说明

第一次出现“非靶向代谢组学”时口头解释：**不预先限定要测哪些分子，尽可能广泛地采集样本中的代谢信号。**

### 转场句

“那么，一张串联质谱究竟提供了什么信息，又为什么很难反推出结构？”

## 第 3 页｜科学问题：从碎裂结果反推分子结构

### 页面标题

**一张 MS/MS 谱图是分子碎裂留下的观测；任务是从不完整观测反推出结构**

### 页面内容

用一张三段式图：

1. 待测分子被离子化；
2. 母离子碰撞碎裂；
3. 得到一组 `(m/z, intensity)` 峰。

右侧列出三种根本困难：

- **多解性：** 相同质量或相同分子式可以对应多个结构；
- **条件依赖：** 仪器、碰撞能量、加合物会改变谱图；
- **开放世界：** 真正分子可能不在现有谱库或候选库中。

### 讲稿

“MS/MS 可以理解为一次受控的分子破碎实验。仪器先选择一个母离子，再让它发生碰撞，最后记录每个碎片的质荷比和相对强度。一张谱图本质上是一组二维观测点。

困难在于，这个反演不是一一对应。多个异构体可能质量相同，也可能产生非常接近的碎片；同一个分子在不同仪器或碰撞能量下，谱图又会变化；更现实的是，真正的分子可能从未进入任何参考谱库。

所以我们希望研究的，不是简单地在已有名称中做分类，而是让系统在化学空间中进行有物理约束的结构推断，并且知道什么时候证据不足。”

### 必须避免的说法

- 不说“质谱就是分子的指纹”，这会让听众误以为一一对应。
- 不说“只要算力足够就一定可以破解”，因为真值缺失和信息不可辨识不能由算力自动消除。

### 转场句

“要把这个科学问题交给 AI 系统，第一步是把每条输入记录定义清楚。”

## 第 4 页｜输入到底是什么

### 页面标题

**最小输入是一张峰表和母离子信息；实验条件是决定可迁移性的必要上下文**

### 页面内容

页面中央放一条标准输入记录：

```text
spectrum_id
peaks = [(m/z_1, intensity_1), ..., (m/z_n, intensity_n)]
precursor_mz
ion_mode / charge / adduct
collision_energy / instrument_type（如有）
retention_time（如有）
```

页面右下角写数据格式：

- 仪器和公共仓库：`mzML / mzXML`；
- 参考谱库交换：`MGF / MSP / JSON`；
- 训练计算：清洗后转为 `HDF5 / tensor`；
- 实验设计与样本信息：`ISA-Tab / TSV / JSON metadata`。

### 讲稿

“对模型而言，最基本的输入不是一张图片，而是一张峰表。每个峰由质荷比和相对强度组成，同时要给出母离子的质荷比。电离模式、电荷和加合物决定质量怎样对应到中性分子；仪器类型和碰撞能量会影响碎裂；保留时间则提供色谱上的补充信息。

原始数据通常以 mzML 或 mzXML 保存，谱库常见 MGF、MSP 或 JSON。进入大规模训练前，可以统一清洗并转成适合随机读取的 HDF5 或张量格式。这里需要强调：实验条件不能随意丢掉，否则系统可能把不同仪器造成的变化误当成结构差异。”

### 审核提示

页面不展示本组内部固定峰数、模型 token 或网络结构，避免把“科学任务输入”误讲成“某一实现的输入”。

### 转场句

“这些输入数据并不是来自一个单独数据库，而是由五类角色不同的数据共同组成。”

## 第 5 页｜不要按数据库罗列，要按数据角色组织

### 页面标题

**完整数据栈包含五类角色；不同数据库不能用一个“优先级”混排**

### 页面内容

用从左到右的一条数据链：

1. **无标注谱图语料**：学习真实谱图分布；
2. **带结构参考谱库**：提供谱图—分子配对；
3. **候选结构与化学知识库**：定义可搜索结构空间；
4. **冻结基准**：在有真值的任务上比较模型；
5. **真实研究队列与标准品**：验证跨域表现和科学可用性。

每类只列 1–3 个代表资源：

- 无标注：MassIVE-GNPS / GeMS；
- 参考谱库：MoNA、MassBank，NIST（授权）；
- 候选与知识：PubChem、HMDB，必要时补 KEGG/MetaCyc；
- 基准：MassSpecGym；
- 真实数据：MetaboLights，例如 MTBLS13729；标准品混合物或实验室留出谱。

### 讲稿

“这页是整个数据部分最重要的组织方式。我们不建议把数据库按体量或知名度排成一张表，因为它们解决的不是同一个问题。

MassIVE 和 GeMS 的价值是规模大、绝大多数没有结构标签，适合学习真实谱图分布。MoNA、MassBank 这类参考谱库有谱图和已知结构配对，可以提供监督和检索参考。PubChem、HMDB 提供候选分子及其结构标识。MassSpecGym 的作用是冻结评测，而 MetaboLights 的真实研究队列用来检验系统离开标准谱库后还能不能工作。

因此，MOA 这类药物扰动图谱可以在下游检验注释是否产生有意义的生物学关联，但它不应替代 MoNA 或 MassIVE，成为谱图结构学习的主要输入。”

### 转场句

“接下来用 DreaMS 的公开数据路线说明，这五类数据在规模上分别是什么量级。”

## 第 6 页｜DreaMS 证明了无标注谱图可以形成基础模型语料

### 页面标题

**MassIVE 提供仓库级真实谱图，DreaMS 将其中高质量子集整理为可训练语料**

### 页面内容

建议只展示四个数字，并在数字下说明口径：

- `338,649` 个 MassIVE-GNPS 文件被纳入初始筛选；
- 其中 `249,422` 个文件包含 MS/MS；
- 清除空谱和非法峰后约 `714 million` 张 MS/MS；
- 用于 DreaMS 预训练的高质量去冗余 `GeMS-A10` 约 `24 million` 张谱。

旁边放格式与来源：

- 来源：截至 2022 年 11 月 MassIVE 中标记为 GNPS 代谢组研究的数据；
- 原始格式：mzML / mzXML；
- 整理格式：带部分实验元数据的 HDF5 数值张量；
- 标签：绝大多数没有分子结构标签。

### 讲稿

“DreaMS 最有启发性的地方，不是某一个网络结构，而是证明公开仓库已经具备基础模型级别的数据规模。作者从 MassIVE-GNPS 中筛选了三十多万个文件，清除空谱和非法记录后得到约 7.14 亿张 MS/MS。真正用于预训练的最高质量去冗余子集 GeMS-A10 约为 2400 万张谱。

这些谱大多没有结构标签，但它们保留了真实仪器、真实样本和真实碎裂条件的分布。因此，大算力的第一项价值是从海量无标注观测中学习稳定的谱图表示，而不是只在一个小型标准谱库上拟合名称。”

### 严谨性注释

不要把 `714 million`、`24 million` 和 DreaMS Atlas 的 `201 million` 混成同一个“训练集大小”。它们分别是清洗后的完整 GeMS、预训练子集 GeMS-A10、Atlas 所代表的谱图规模。

### 转场句

“但无标注谱图不能单独告诉我们结构名称，因此还需要较小、但有真值的参考谱库和评测集。”

## 第 7 页｜带真值数据、候选库和评测集分别是什么

### 页面标题

**小规模真值负责对齐结构，大规模候选库负责定义搜索空间，冻结基准负责判定能力**

### 页面内容

用三列，不要做十几个数据库卡片。

#### 参考谱库：MoNA

- 范围：带已知小分子结构或标识符的参考质谱；
- 信息：MS/MS 峰、precursor/adduct、碰撞条件、SMILES/InChIKey 等；
- 格式：MSP、JSON、SDF；
- DreaMS 论文使用的 MoNA 划分：`25,319` 张训练谱 / `5,524` 个分子，`3,557` 张验证谱 / `831` 个分子；合计约 **2.9 万张谱、6,355 个分子**。

#### 候选结构库：PubChem / HMDB

- 信息：结构、分子式、精确质量、SMILES、InChI/InChIKey；
- 格式：SDF、SMILES、XML/JSON/CSV；
- 作用：依据母离子质量或分子式生成候选，不等同于“有参考谱”。

#### 冻结基准：MassSpecGym

- 约 `231,104` 张标准化 MS/MS，约 `29k` 个独特分子结构；
- 来源包括 MoNA、MassBank、GNPS 和研究组数据；
- 提供质量候选和分子式候选，单个 query 最多 256 个候选；
- 提供强调结构泛化的训练/验证/测试划分。

### 讲稿

“这三类数据必须分开理解。MoNA 的谱图带有结构标签，能够建立谱图和分子之间的对应关系。DreaMS 论文真正用于相似性微调的 MoNA 规模大约是 2.9 万张谱、6355 个分子，这说明有真值的数据远小于无标注数据。

PubChem 和 HMDB 主要提供分子结构和属性。一个结构在 PubChem 里，并不代表它一定有可用的实验 MS/MS 谱。它们更适合根据母离子质量或分子式产生候选集合。

MassSpecGym 则负责把任务冻结下来：给定一张谱和一个候选集合，模型能不能把正确结构排到前面。它还专门设计了更严格的结构隔离划分，降低训练和测试中近重复结构造成的虚高。”

### 合规说明

NIST 谱库是重要资源，但不是完全公开数据。主讲只说“在获得授权时可作为补充参考谱库”，不要将其列入默认公开数据包。

### 转场句

“公开基准回答模型是否会做题，真实研究数据回答它能否离开题库工作。”

## 第 8 页｜MTBLS13729 只是一个真实压力测试，不是课题边界

### 页面标题

**真实队列用于检验端到端可用性；MTBLS13729 是示例，不是专门为它训练模型**

### 页面内容

左侧写数据事实：

- MetaboLights 公开研究；
- 4 个 LC–MS 面板 × 60 个样本，共 240 个 mzML 文件；
- 同时提供 ISA-Tab/assay 元数据；
- 真实组织样本、不同色谱与离子模式；
- 大量谱图没有标准品真值。

右侧写它在项目中的角色：

1. 测试从 mzML 到候选注释的完整流程；
2. 检查模型在真实样本、不同采集条件下是否稳定；
3. 发现值得购买标准品或做靶向实验的候选；
4. 不能用它直接计算所有未知谱图的 Top-1 准确率。

### 讲稿

“我们可以用 MTBLS13729 解释真实应用，但一定要把它放在正确位置。它是一个公开的结直肠癌代谢组学队列，包含四个分析面板和 240 个 mzML 文件。这样的数据能检验从原始文件、谱图提取、候选检索到生物学分析的完整流程。

但它不是我们的专属训练集，也不是整个课题只服务的对象。更重要的是，真实队列中大多数未知峰没有标准品真值，所以不能把模型给出的名称直接当作正确答案。它的作用是做外部压力测试、产生可验证候选，并把最有价值的候选送到后续标准品或靶向实验。”

### 必须避免的说法

- 不展示本组在该队列上的具体候选或算法提升；
- 不说“用 MTBLS13729 证明模型准确率提高”；
- 不把相关性、丰度差异或通路富集说成结构真值。

### 转场句

“现在数据边界已经清楚，下一步要定义系统最后究竟应该交付什么。”

## 第 9 页｜最终目标不是强制给一个名字，而是交付可验证的结构结论

### 页面标题

**系统应输出候选、置信度、证据与拒答，而不是对每张谱强行命名**

### 页面内容

给定输入谱图，系统输出四层结果：

1. **候选排序：** Top-k 结构，SMILES/InChIKey/分子式；
2. **校准置信度：** 该候选为正确结构的可信程度；
3. **证据说明：** 支持它的碎片、质量约束、实验条件与冲突；
4. **开放世界处理：** 候选库不充分时，退到结构类别、相似骨架、分子式或“未知”，并明确拒答。

底部用一句话定义成功：

> **在正确结构存在于候选池时可靠地把它排到前列；不在候选池或证据不足时，不制造虚假的确定性。**

### 讲稿

“如果把最终目标只写成‘输出一个代谢物名称’，这个问题会被定义得过于粗糙。我们希望的交付至少包括四部分：候选排序、经过校准的置信度、可检查的谱学证据，以及在证据不足时的拒答。

这里有两个不同问题。第一，正确结构在候选池里，系统能不能把它排到前面；第二，正确结构根本不在库里，系统能不能意识到这一点，而不是从错误候选中挑一个最像的并高置信输出。对科学应用而言，第二种能力与第一种同样重要。

最终我们希望把未知谱图分成三类：可以高置信注释的、只能定位到结构家族的、目前仍应保留为未知的。这样的结果才适合进入后续实验。”

### 转场句

“因此，评价不能只有一个准确率，而要分成计算真值、实验真值和真实应用三层。”

---

## 第 10 页｜第一层评价：冻结计算基准，回答模型能力是否真的变强

### 页面标题

**模型比较必须锁定数据划分、候选池和评测代码，才能把提升归因于模型本身**

### 页面内容

#### 固定协议

- 按分子结构划分训练、验证和测试；同一分子的不同谱不能跨集合泄漏；
- 候选池固定：按质量误差或已知分子式构建；
- 同一输入预处理、同一候选聚合、同一并列规则；
- 测试集在模型和阈值冻结后只运行一次。

#### 核心指标

- Hit/Recall@1、@5、@20；
- MRR 或真实结构平均排名；
- Top-1 结构距离，例如 MCES@1；
- 近异构体、跨仪器、跨碰撞能量等分层表现；
- 置信度校准和 accuracy–coverage 曲线；
- corrected / introduced：纠正了多少旧错误，又引入了多少新错误。

### 讲稿

“怎样证明模型能力真的增强？第一层是在有结构真值的冻结基准上比较。最关键的不是选哪个指标，而是先把协议锁死。

同一个分子的多张谱不能一部分在训练、一部分在测试；候选池、质量窗口、预处理和并列规则必须一致；测试集要在模型和阈值全部冻结后再运行。否则几乎任何提升都可能来自数据泄漏或候选集合变化。

指标上，Top-1 回答第一名是否正确，Top-5 和 Top-20 回答系统是否能缩小实验搜索范围，MRR 反映整体排序。对完全相同结构之外，还应报告第一名与真值的结构距离。最后要看纠正和新增错误，避免总体均值掩盖某一类分子明显退化。”

### 重要口径

不同数据集、候选规则或测试面板的百分点不能直接相加。DreaMS 或本组任何历史结果只有在 query、candidate 和评价协议完全一致时才可比较。

### 转场句

“计算基准能够比较模型，但真实世界的‘鉴定正确’需要更高一级的实验标准。”

## 第 11 页｜第二、三层评价：标准品确认与真实外部验证

### 页面标题

**Top-1 是计算检索正确；真实样本中的确认身份仍需标准品和正交证据**

### 页面内容

用三级阶梯：

#### A. 封闭计算真值

已知谱图 + 已知正确结构 + 固定候选池。  
结论用语：**检索正确 / 排名提升。**

#### B. 盲标准品与跨实验室测试

不向模型公开身份的标准品混合物；不同仪器、碰撞能量和实验室重复采集。  
检查精确质量、MS/MS 和保留时间的一致性。  
结论用语：**外部泛化 / 标准品确认。**

#### C. 真实队列

在 MetaboLights 等研究中运行；报告覆盖率、置信度、重复性、候选完整率和拒答率；高价值候选再购买标准品或做靶向验证。  
结论用语：**结构注释 / 待验证候选。**

底部写清置信度边界：

- 与同条件标准品比较至少两种独立、正交的分析性质；常见实践同时核对准确质量、RT 和 MS/MS：可支持 Level 1 确认；
- 公共谱库匹配但没有本实验标准品：通常只能支持 Level 2 级别的概率性结构注释；
- 仅有分子式、精确质量或结构家族：必须进一步降级表达。

### 讲稿

“这页是语言和科学边界的核心。封闭基准上的 Top-1 正确，说明模型在给定候选中找到了已知真值，但不等于现实样本中的化学身份已经被确认。

更强的验证是盲标准品测试：把身份暂时对模型隐藏，在不同仪器和实验室采集，看系统能否稳定找回。Level 1 身份需要与同条件标准品比较至少两种独立、正交的分析性质；实际工作中通常同时核对保留时间、准确质量和碎裂谱。

对于真实队列，如果只有公共谱库匹配而没有本实验标准品，我们应该称为结构注释或 Level 2 候选，而不是确认鉴定。模型的价值是大幅缩小需要做实验验证的范围，而不是取消实验真值。”

### 转场句

“有了可冻结的数据和可证伪的终点，这个问题才真正适合大规模 Agent 体系。”

## 第 12 页｜为什么值得联合推进，以及希望今天达成什么

### 页面标题

**这是一个可并行探索、可自动反驳、又有实验终点的规模化 AI for Science 任务**

### 页面内容

左侧“适合规模化的原因”：

1. **数据规模足够：** 千万到亿级无标注谱图，十万级带标注基准；
2. **搜索空间丰富：** 数据清洗、表示学习、结构生成、候选检索、碎裂推理、置信度与拒答均可形成独立研究单元；
3. **实验可自动化：** Agent 可提出假设、生成实验、运行训练、做消融和压力测试；
4. **结论可证伪：** 冻结基准和盲标准品可以直接否定无效方案；
5. **科学回报明确：** 把更多未知谱图转化为可验证的化学候选。

右侧“建议的第一步”：

- 共同冻结一版**任务说明书**：输入、输出、允许使用的数据和禁止泄漏边界；
- 共同建立一套**公共数据清单与许可证台账**；
- 选择一个**有结构真值的计算基准**和一个**真实外部队列**；
- 先做小规模可行性验证，再决定是否扩展到大规模 Agent 搜索。

页面最下方只留一个讨论问题：

> **贵组是否愿意和我们一起，把这个问题先定义成一套可运行、可否证、可扩展的联合基准？**

### 讲稿

“我们认为这个问题适合规模化 AI for Science，不只是因为数据多。更重要的是，它同时具备广阔的计算搜索空间和明确的否证机制。不同 Agent 可以围绕数据质量、谱图表示、结构候选、碎裂解释和可靠性提出假设；每个假设都必须回到同一套冻结基准和盲标准品验证，不能只看训练损失或局部案例。

我们今天并不希望直接规定贵组采用哪一种算法，也不希望把已经做过的内部尝试作为合作前提。更合适的第一步，是双方共同冻结任务说明书、数据清单和评价协议，选择一个计算基准与一个真实外部队列，先做一轮可行性验证。

我们很想听听您的判断：这个问题是否适合贵组的 Agent 与算力体系；如果适合，您认为第一阶段应优先攻数据规模、结构推理，还是可靠性评价？”

## 附录 2｜建议的数据切分

1. **无标注预训练集：** GeMS-A10 等；可用于学习谱图分布，但不得引入测试结构标签。
2. **带标注训练/验证集：** MoNA、MassBank 等；按结构簇划分。
3. **冻结计算测试集：** MassSpecGym 的结构隔离测试集或双方重新冻结的外部标准谱面板。
4. **盲标准品集：** 身份对训练人员隐藏，仪器和实验室独立采集。
5. **真实外部应用集：** MTBLS13729 等 MetaboLights 队列；只评价覆盖、稳定性、置信度与后续验证命中，不虚构未知谱真值。

## 附录 3｜模型能力变强的最低证据门槛

只有同时满足以下条件，才建议说“模型能力增强”：

1. 同一冻结 query 和 candidate 协议；
2. 测试身份未进入监督训练，且结构近邻泄漏受控；
3. Top-1/Top-k、MRR 与结构距离至少两类指标同向；
4. 近异构体和跨条件子集没有不可接受退化；
5. 置信度校准没有恶化，或能以合理拒答换取更高正确率；
6. 统计分析按分子或分子式簇配对，而不是把同一分子的重复谱当成独立样本；
7. 至少一次独立外部或盲标准品验证；
8. 报告新纠正与新引入错误，不只报告平均百分点。

## 附录 4｜可供 A 教授讨论的研究问题，不预设具体算法

- 无标注谱图规模继续扩大时，结构信息是否持续增长，还是受到数据质量和重复性的上限约束？
- 如何让系统区分“正确结构不在候选库”与“模型没有识别出来”？
- 如何利用质量守恒、子结构和中性丢失等化学约束，减少近异构体混淆？
- 如何在仪器、碰撞能量、离子模式和实验室变化下保持表示稳定？
- 如何让 Agent 自动提出、执行并反驳碎裂假设，而不是只自动调参？
- 如何把预测置信度转化为标准品购买和实验验证的优先级？

# 五轮适配审核

## 1. 场景适配审核

**通过条件：** 这是一次“邀请共同定义科学问题”的首次交流，不是项目答辩、成果路演或算力申请。

- 已删除本组算法路线、内部试验结果和性能数字；DreaMS 只作为公开基础工作和数据范例。
- 不把 MTBLS13729 讲成合作必须服务的唯一数据集，只作为真实外部应用示例。
- 不在首次交流中给对方分派任务；使用“建议共同冻结”“希望听取判断”等协商表达。
- 结尾只请求进入联合可行性验证，不请求当场承诺大规模资源。

## 4. 逻辑性审核

1. 大量真实信号没有身份，形成科学瓶颈；

4. 因此需要无标注、带真值、候选、基准和真实应用五类数据；

6. 因为“排名第一”不等于实验确认，评价必须分三层；
