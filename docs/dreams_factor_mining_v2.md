# DreaMS 微调权重的隐式化学因子挖掘方案 v2

**日期：2026-08-11**

## 一、先修正当前问题

上一轮只分析了 `ssl_model_server.pt` 的最终 precursor embedding，使用 5,706 个分子训练简单 PCA/SAE。它没有分析官方微调权重、七层中间激活和 peak-token embedding，因此不能回答“微调究竟新增或强化了哪些化学因子”。

本地 checkpoint 审计确认：原始自监督模型与官方微调模型具有相同主干结构和 68 组同名参数，可以对同一张谱图逐层配对比较。参数范数初查显示，前两层 attention/FFN 的相对变化约为 2.44%–2.45%，第七层约为 1.99%；Fourier m/z 编码器个别权重变化达到 4.65%。权重差只能定位检查区域，不能直接解释为化学因子。

## 二、问题1：如何系统挖掘微调权重中的因子

### 1. 建立原始模型—微调模型的成对激活库

对同一张谱图同时运行：

- (M_0)：原始自监督 DreaMS；
- (M_1)：官方对比微调 DreaMS。

每层保存两类激活：

- precursor token：分子/谱图全局表征；
- peak token：单个谱峰及其上下文表征。

不能只保存最终 1024 维向量，因为微调可能在早期质量编码或中间注意力层形成局部因子，最终层只保留检索所需的组合结果。

### 2. 先定位变化层，再分解因子

第一步使用 CKA 比较 (M_0) 与 (M_1) 各层激活：

\[
\operatorname{CKA}(H_0^{(l)},H_1^{(l)})
\]

CKA回答“哪一层的表示发生了系统变化”，不负责给因子命名。只在变化最大的1–2层训练后续模型，减少盲目计算。

### 3. 使用 Crosscoder 做 base—finetune model diffing

对同一谱图、同一层的成对激活训练共享稀疏编码：

\[
z=\operatorname{TopK}\!\left(E_0h_0+E_1h_1+b\right)
\]

\[
L_{\mathrm{cross}}=
\lVert h_0-D_0z\rVert_2^2+
\lVert h_1-D_1z\rVert_2^2+
\lambda_s\lVert z\rVert_0
\]

每个稀疏因子同时具有原始模型和微调模型的解码方向。根据两个解码器的方向、范数和激活变化，可将因子分为：

- 共享因子：两个模型中均存在；
- 微调增强因子：两边存在，但微调后激活或下游贡献增强；
- 微调抑制因子：微调后贡献下降；
- 微调特异因子：主要出现在 (M_1)；
- 条件/噪声因子：主要随仪器、碰撞能量或峰数变化。

这一步比单独对微调 embedding 训练 SAE 更直接，因为研究对象本身就是“微调改变了什么”。

### 4. 用同分子多条件谱图打破非线性因子的不可识别性

纯无监督非线性分解存在旋转和重参数化歧义。利用同一分子的多碰撞能量、多仪器和多加合物谱图作为成对视图：

- 化学稳定因子应在同分子多条件谱图中保持；
- 条件因子允许随碰撞能量、仪器和加合物变化；
- 同一谱图随机遮峰后，稳定因子不应大幅漂移。

可以加入：

\[
L_{\mathrm{view}}=
\lVert z_{\mathrm{chem}}(x_i)-z_{\mathrm{chem}}(x_j)\rVert_1,
\quad IK14_i=IK14_j
\]

InChIKey只用于说明两张谱图是同一分子的不同观测，不用于定义因子的化学含义。

### 5. 数据规模与抽样

不能再只用5,706个分子，也不能让重复谱图最多的分子支配训练。

| 数据层 | 建议规模 | 作用 |
|---|---:|---|
| 层变化定位 | 30,000–50,000张平衡谱图 | 计算七层CKA，选择重点层 |
| Crosscoder发现 | 100,000–300,000张谱图 | 训练共享/微调特异稀疏因子 |
| 多条件配对 | 至少50,000对同分子谱图 | 区分化学稳定因子与实验条件因子 |
| 化学注释 | 10,000–20,000个结构已知分子 | 后验关联子结构、规则与motif |
| 外部确认 | MassSpecGym Murcko隔离fold | 验证跨骨架、跨数据来源复现 |

训练时采用“每个分子每轮最多抽取2–4张谱图”或按分子谱图数倒数加权，并按前体质量、仪器、碰撞能量、加合物和谱峰数分层。

## 三、问题2：因子应该是什么形式

因子不应是一条质量数字，也不应预设“一维对应一条规则”。一个合格因子应是带证据的稀疏概念对象：

\[
F_k=\{a_k,D_k^{(0)},D_k^{(1)},l,t,E_{\mathrm{spec}},E_{\mathrm{struct}},E_{\mathrm{cond}},Q\}
\]

- (a_k)：每张谱图或每个峰上的稀疏激活强度；
- (D_k^{(0)},D_k^{(1)})：原始模型和微调模型中的解码方向；
- (l)：所在网络层；
- (t)：precursor级或peak-token级；
- (E_{\mathrm{spec}})：精确碎片、质量差、峰对和Mass2Motif证据分布；
- (E_{\mathrm{struct}})：富集的局部结构、分子家族和MCES邻域；
- (E_{\mathrm{cond}})：对碰撞能量、仪器、加合物的敏感性；
- (Q)：稳定性、支持度、跨数据集复现和干预结果。

建议建立三级因子：

1. **全局结构因子**：在 precursor token 中激活，描述分子家族或结构环境；
2. **局部碎裂因子**：在 peak token 中激活，描述一组共同出现的精确峰、质量差或中性丢失；
3. **关系因子**：描述多个局部因子的共现、互斥或顺序，接近完整碎裂motif。

只有当全局因子与局部碎裂因子在独立分子中稳定对应，才能命名为候选化学机理。其余先标记为“结构因子”“条件因子”或“未解释因子”。

## 四、问题3：如何建立因子与化学规则的关系

### 1. 规则必须先从数字列表变成结构化知识对象

每条规则至少应记录：

- 精确质量/分子式；
- peak、neutral loss、isotope、rearrangement等类型；
- 极性、加合物、荷电状态和质量容差；
- 所需结构环境；
- 文献或数据库来源；
- 支持分子数、跨仪器支持和置信等级；
- alias group，用于合并MassBank中重复表达同一质量现象的记录。

### 2. 构建因子—规则二部图

设因子激活矩阵为 (A_{ik})，规则命中矩阵为 (R_{ij})。对每个因子—规则组合，在骨架隔离的训练/验证划分中拟合：

\[
\Pr(R_{ij}=1)=
\sigma\!\left(\beta_{kj}A_{ik}+\gamma^\top C_i\right)
\]

(C_i) 包含前体质量、峰数、碰撞能量、仪器、加合物等混杂因素。评价应报告：

- 相对“仅混杂模型”的 ΔAUPRC；
- 条件优势比和置信区间；
- 跨Murcko scaffold复现；
- Benjamini–Hochberg校正后的q值；
- 不同仪器/碰撞能量分层的一致性。

规则高度稀疏且类别失衡，Pearson相关和总体ROC-AUC不适合作为主要依据。

### 3. 关系应是多对多

- 一个因子对应多条规则：可能表示一个完整碎裂motif；
- 多个因子对应一条规则：可能把“脱水”拆成不同结构背景；
- 因子与现有规则无关：可能是新化学模式，也可能是条件/噪声；
- 规则相关但峰级干预失败：只能称统计关联。

### 4. 用峰级干预验证方向性

根据 peak-token 因子和规则定位候选峰集合 (P_k)，比较目标删除与匹配随机删除：

\[
\Delta a_k^{\mathrm{target}}
=a_k(x)-a_k(x\setminus P_k)
\]

\[
\Delta a_k^{\mathrm{random}}
=a_k(x)-a_k(x\setminus P_{\mathrm{matched}})
\]

只有当目标删峰导致的因子激活下降显著大于同数量、同强度的随机删峰，且检索变化方向符合预期，才能认为规则证据参与了该因子。

### 5. 最终关系类型

- 已知规则再发现；
- 广义规则的结构背景细分；
- 多条规则组成的碎裂motif；
- 当前规则库缺失的新候选；
- 实验条件/污染因子；
- 暂不可解释因子。

规则只负责后验命名和验证。未完成独立复现与峰级干预的因子，不进入规则库核心层，也不参与embedding距离监督。

## 五、建议的实际执行顺序

1. 用30,000–50,000张平衡谱图同时跑原始与官方微调模型，输出七层precursor激活，计算CKA。
2. 选择变化最大的两层；扩展至100,000张谱图，缓存成对precursor激活和抽样peak-token激活。
3. 训练三随机种子的Base–Finetune Crosscoder，区分共享、增强、抑制和微调特异因子。
4. 用同分子多条件谱图检验化学不变性，剔除仪器/碰撞能量因子。
5. 在独立结构集上建立因子—子结构—Mass2Motif—规则的多对多证据图。
6. 对少量高置信候选做峰遮蔽干预。

第一步只做前向推理和CKA，不训练DreaMS，成本最低；CKA确认哪些层真正发生变化后，才决定Crosscoder训练规模。
