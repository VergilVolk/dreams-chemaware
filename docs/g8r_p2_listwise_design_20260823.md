# G8R P2：受保护的候选组内排序方案

## 1. 要解决的问题

RAW-v1 在已消耗的 g8r_val 开发协议上将 Recall@1 从 0.8081 提高到
0.8516（+4.35 个百分点，44 个修正、17 个新增错误），但冻结盲测仅呈
非显著正方向。因此 P2 不把这个开发集数字当作新模型结论，只把它作为
**实现兼容性门**：新管线开始前必须逐项复现该数字，证明候选图、特征、
分数和指标口径没有漂移。

P2 的训练目标从“独立判断一个谱图对”改为“在同一查询的完整候选组内，
让正确分子排在所有错误分子之前”。

## 2. 数学形式

对查询谱图 q、候选谱图 j，冻结 DreaMS 给出基础余弦分数

\[
s^0_{qj}=\cos(z_q,z_j).
\]

模型只学习一个有界残差：

\[
s_{qj}=s^0_{qj}+\Delta_{\max}\tanh f_\theta(x_{qj}),
\qquad |s_{qj}-s^0_{qj}|\le \Delta_{\max}.
\]

最后一层以零初始化，因此训练开始时逐对满足 \(s_{qj}=s^0_{qj}\)，不会
因为随机初始化先破坏 DreaMS。候选分子的分数与部署端一致，对该分子的
所有候选谱取最大值：

\[
S_{qm}=\max_{j\in m}s_{qj}.
\]

组内 listwise 损失为：

\[
L_{\mathrm{list}}=-\log\frac{\exp(S_{q,+}/\tau)}
{\sum_m\exp(S_{qm}/\tau)}.
\]

对 DreaMS 原本已排对的查询，再增加安全约束：

\[
L_{\mathrm{safe}}=
\max\{0,\,M_q^0-\epsilon-M_q\},
\]

其中 \(M_q\) 是正确分子与最强错误分子的分差。该项限制模型不能通过
牺牲大量原本正确的查询换取少量修正。总损失为

\[
L=L_{\mathrm{list}}+\lambda_sL_{\mathrm{safe}}
+\lambda_r\|\Delta/\Delta_{\max}\|_2^2.
\]

## 3. 数据纪律

1. P2 训练只使用 P3 封存时生成的 `real_train_primary` 行；模拟谱不进入
   首版模型。
2. P3 的任何查询身份既不能成为 P2 查询，也不能作为 P2 候选。
3. 候选组固定为 strict 10 ppm、同加合物、排除查询自身谱；每个候选分子
   保留其候选谱，并在模型内按 max 聚合。
4. 交叉验证按分子式隔离；同一分子式不会跨训练/验证折。
5. 外层折只负责评价；早停轮次由内层分子式折选择，避免用外层结果挑轮次。
6. P3 不参与超参数、轮次、阈值或模型选择；模型冻结后才能评价一次。

## 4. 开始训练前的硬门

### 数学门

- 零初始化逐元素等于 DreaMS；
- 残差不超过预注册上限；
- 分子 max 聚合与部署端一致；
- 并列分数按检索失败处理；
- listwise 梯度提高正确候选分数、降低错误候选分数；
- 安全项能识别并惩罚对正确基础分差的破坏。

### 数据门

- P3 状态和三项封存哈希完全匹配；
- P2/P3 的 IK14 重叠为 0；
- P2 所有行均为真实谱、train fold；
- 有足够多的有效 strict-10ppm 查询和 MCES 0–2 查询。

### 兼容性复现门

- baseline Recall@1 = 0.8080645161；
- frozen RAW-v1 Recall@1 = 0.8516129032；
- corrected / introduced = 44 / 17；
- gate coverage = 0.4645161290。

任一数值不符即停止，不进入缓存构建或训练。

## 5. 模型导出门

嵌套分子式隔离 OOF 必须同时满足：

- 总体 Recall@1 不下降；
- near（MCES 0–2）Recall@1 不下降；
- MRR 不下降；
- corrected 不少于 introduced；
- Recall@1 至少提高 3 个百分点，并且分子式聚类 bootstrap CI 下界大于 0。

未过门只保存诊断报告，不导出模型。

## 6. 结论边界

复现 +4.35 个百分点只能证明旧开发结果和新实现完全对账，不能提前保证
P3 也提高约 4 个百分点。P2 是否优于官方 DreaMS，最终只由冻结模型在
封存 P3 上的一次性结果决定。
